三、七段主链路

适配器的职责可以用一句话概括：把“人体几何”翻译成 DiT 能听懂的“增量”，并只在中途注入、不改主干一行代码。

① 静态 vs 动态分离

条件推理与桥接每张图只算一次并缓存；控制残差每个去噪步重算。 这样既省算力，又让控制能“看着当前噪声状态”调整——这就是它比一次性注入更强的根本原因。

② 零初始化 = 可证明的起点

所有残差头（V6.3 的 12 个，加 detail / face / hand 各 6 个）初值为全零。 因此「装适配器」与「不装适配器」的输出在初始化时差异 ≤1e-6——这保证基线行为不变，是接口不变量，而非控制效果。

③ 强度调度按分支独立

每条支路有独立的去噪进度窗：face 在 0.35–1.0 才介入（先定结构、后补细节）； hand 从 0.15 起步，纹理到 0.65 才放行。像画画：先起形，后上细节。

五、V6.6 手部分支为什么会是新东西

核心矛盾：VAE 是 8× 下采样。一张 512×512 的图进到潜空间只剩 64×64， 手上那点像素被压到亚像素级——这是手部细节的硬约束，也是全项目反复卡住的根因。 拿它类比：像是在 8 倍缩小的缩略图上改指纹，主干本身根本“看不到”手指。

V6.4 的做法是给「脸+手」开一条共享支路并按区域门控，方向对但两支互相牵制。V6.6 把手单独拆出来， 并采用一条与脸完全不同的技术路线：在外面的 ROI 上把手画好，再贴回全局 token。

归属权重，单只手的 掩码强度保持原样 —— 既不重复，也不削弱。 对外观泄漏的防线 手的外观只从源帧取 DINOv2 patch，目标帧 RGB 完全不参与。 推理时不需要目标帧 RGB —— 这是“真编辑”而非“换皮”的前提。 另有 hand_quality_gate：对手小 / 置信度低 / 出界的样本 标记为待精修，可由 ViTPose 结果替换（离线，不默认开启）。

几何编码

45 维轴角手部姿态转为 96 维 6D 旋转表示（VTON 风格），加上 21 点骨骼、 16×16 高斯热图与深度切片，构成 23 通道局部输入。

外观编码

源手区域取 DINOv2-Giant patch 特征，经重采样器压成 8 个外观 token， 以 Key/Value 形式供几何 Query 检索——只借纹理，不借身份。

离线增强钩子

预留 HandRefiner 导出接口与质量门控，属于「可选后处理」， 默认生成链路绝不触发，避免引入不可复现的外部依赖。

八、风险与待办

R1 · 文档与配置滞后两个版本（高优先级）
configs/adapter_v6_architecture.json 版本号仍是 6.3-dynamic-deepgen-interface-v1， docs/adapter_v6_architecture.md 标题也仍是 V6.3。 两者完全没有覆盖 detail / face / hand 三支。当前架构真实版本是 v6.6（见 checkpoint.ARCHITECTURE_VERSION）。 这意味着任何依赖配置文件的复现流程都会得到错误的架构描述。
R2 · 远端仓库存在大额未提交改动
git status 显示 51 个文件变更 / 净 −3,798 行，其中包括 任务书等 3 个 .docx 显示为删除、train_adapter.py 与 test_control_signals.py 被删、 eval_iper_v6.py 等处于修改态。这些删除是否有意，需要裁决；否则一次误操作即可造成不可回溯的丢失。
R3 · 细节分支的 ROI 外泄漏未被约束
face 支路在人脸 ROI 之外的扰动 MSE 随训练步数单调上升（iPER 达 0.0695，是 TikTok 的 2.5 倍）。 当前强度调度只控制「何时介入」，没有约束「在哪儿介入」的软边界。 建议在损失里显式加入 ROI 外一致性项，或收紧 region mask 的衰减带宽。
R4 · 双人交互这一硬指标缺少证据链
任务书要求二阶段双人交互主观合理率 ≥90%，而 Hi4D 目前只有 1 步冒烟。 这是验收链上最大的一块空白，优先级应高于继续打磨单支细节。
R5 · 系统盘空间紧张
/dev/sda2 仅剩 66 GB（97% 已用），而 /data 有 22 TB 仅用 2%。 继续训练前应把大文件（数据集、检查点）迁往 /data，否则一次缓存写入就可能触发中断。
R6 · 本地与远端双向漂移：远端领先本地 3 个提交（V6.6 全部代码）； 同时远端存在大量本地没有的未提交改动。两侧已不具备「互为单位置副本」的性质， 建议尽快确定单向同步策略。
