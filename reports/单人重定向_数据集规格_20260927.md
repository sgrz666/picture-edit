# 单人跨体型重定向 · 数据集规格定义

**日期**：2026-09-27
**任务**：输入 A（外貌来源，含体型）+ B（姿态参考），输出「A 的外貌与体型 + B 的姿态」
**用户提出**：能否用 AI 模型生成/编辑来构建数据集
**本文件回答**：需要什么样的数据、必须标注什么、分布要覆盖什么、以及 AI 应该在哪一环介入

---

## 1. 先把"需要什么数据"形式化

训练样本必须是一个**自洽三元组**：

| 字段 | 含义 | 关键约束 |
|---|---|---|
| `I_s` | 源图：该人物在姿态 P_s 下的照片 | 身份 = 目标身份 |
| `C_t` | 目标几何条件：姿态 P_t 的结构化表示 | **必须与 `I_t` 逐像素对齐** |
| `I_t` | 目标图：**同一人物、同一服装、同一体型**在姿态 P_t 下的照片 | 唯一的监督标签 |

**核心约束：`I_s` 与 `I_t` 之间只允许"姿态"这一个变量改变。** 身份、发型、肤色、服装、体型、背景、光照最好全部一致——否则模型学到的不是"换姿态"，而是"换一切"。

这条约束决定了后面所有技术路线的取舍。

## 2. 必须标注的字段（对应适配器实际消费的内容）

适配器 `SMPLXConditionInjector` 的真实输入契约（已实测）：

| 字段 | 形状 | 来源 | 说明 |
|---|---|---|---|
| `normal` | [3,H,W] ∈[-1,1] | **渲染** | 表面法线 |
| `depth` | [1,H,W] | **渲染** | 归一化深度 |
| `part_onehot` | [14,H,W] 二值 | **渲染** | 14 类部位，全零=背景 |
| `pose_heatmap` | [25,H,W] ∈[0,1] | 关节投影 | OpenPose BODY_25 |
| `human_mask` | [1,H,W] ∈[0,1] | **渲染** | 人体轮廓 |
| `smplx_global` | [26] | SMPL-X 参数 | 全局体型/朝向摘要 |
| `relative_geometry` | [11] | SMPL-X 参数 | 单人任务可退化/置零 |
| `contact_raster` | [2,H,W] | **渲染** | 单人任务可退化/置零 |
| `task_id` | int64 | — | `TaskType.SINGLE = 0` |
| `camera` | K,R,t | 设定 | 内参 + 外参 |

**注意最后三项**：单人任务其实不需要 `relative_geometry` / `contact_raster` / person-B 那一整套。当前代码为了复用双人结构把它们保留了。**如果专门做单人数据集，可以把契约裁剪成前 6 项**，能省掉大量无用通道和标注成本。

**此外必须额外标注的（不是给适配器，而是给训练与验收）**：

- **SMPL-X 参数**：`betas`(体型 10+) / `body_pose`(69) / `global_orient`(3) / `transl`(3)
- **逐人分割掩码**（用于算加权损失、算 ROI 指标）
- **源图视角角**（见第 3 节，这是最容易被忽略但最关键的元数据）
- **源图人体占比**与**遮挡比例**
- **面部关键点/嵌入**（用于身份一致性验收）

## 3. 分布必须覆盖的轴 —— 这是整套规格里最重要的部分

### 3.1 从 hard_01 / hard_02 的失败里读出的因果

同一人物、同款服装、同样参数（40 步 / seed 42 / cfg 1.0），只换了一张源图：

| | hard_01 | hard_02 |
|---|---|---|
| 源图视角 | **侧面 / 四分之三背向** | **正面** |
| 源图遮挡 | 身后紧贴另外两人，躯干被挡 | 单人干净 |
| 源图占比 | 较小 | 较大 |
| **输出体型** | **被瘦化，体型丢失** | **保住** |

**结论：失败发生在源图侧，不在目标侧。** 当源图丢失"横向宽度"这个线索时，模型回落到先验中更常见的体型。

**因此数据集必须按"源图可读性"分层，而不是随机采样。** 这是当前所有公开数据集都没做的事。

### 3.2 分层维度

| 轴 | 建议取值 | 为什么必须分层 |
|---|---|---|
| **源图朝向** | 正面(±30°) / 斜(30–70°) / 侧面(70–110°) | 侧视时横向宽度被透视压缩 → hard_01 的根因 |
| **源图遮挡** | 无 / 轻度 / 部分 | 遮挡污染"哪些像素属于主体" |
| **源图人体占比** | >60% / 30–60% / <30% | 小目标时体型不可读 |
| **体型（BMI 档）** | <18.5 / 18.5–25 / 25–30 / 30–35 / >35 | 高 BMI 是模型先验最弱、最需监督的区域 |
| **源→目标姿态差** | 小 / 中 / 大 | 姿态差大时外观保持更难 |
| **服装** | 紧身 / 宽松 / 多层 | 宽松服装掩盖体型轮廓 |
| **目标朝向** | 正面 / 斜 / 侧面 | 目标侧视时模型自由度更大，更易漂移 |

### 3.3 最关键的一条采样规则

> **同一身份 × 同一目标姿态 `I_t` × 多个源视角 `I_s`**

即：让同一个人的同一个目标姿态，配 4–6 个不同视角/遮挡程度的源图。

**理由**：这直接教模型"体型是身份的属性，不随视角改变"。hard_01 的失败正是因为模型没有学到这一条——它把"正面能看到宽"和"侧面看不到宽"理解成了不同的体型。

**这是整个数据集设计里性价比最高的一条规则。**

### 3.4 划分方式

- **按身份划分**（不是按帧）——否则相邻帧泄漏
- **单独留出极端体型测试集**：把 BMI>35 和 BMI<17 的样本**全部留作测试**，训练集只到 30
  → 这样才能回答"模型是学会了体型迁移，还是只记住了见过的体型范围"

## 4. 三条构建路线，以及为什么"纯文生图"不可行

用户提到"用 AI 模型生成编辑来构建数据集"。这个想法方向对，但**必须限制 AI 介入的位置**。

### 路线 A：纯文生图（**不可行**）

用扩散模型按提示词生成 N 张大体型人物照片。

| 问题 | 说明 |
|---|---|
| ❌ 无配对 | 每次生成是独立身份，拿不到"同一人不同姿态"的 `I_s`/`I_t` |
| ❌ 无精确几何 | 只有图，没有 β/θ；只能反拟合 SMPL，误差直接进监督 |
| ❌ 无 GT 目标 | 任务需要"该人物在该姿态下的真实图"，生成模型给不出 |
| ❌ 体型不可控 | 想要 BMI=38 就真的能得到 BMI=38 吗？无法验证 |

**结论：生成模型最不擅长的恰恰是"身份/体型/姿态的精确一致性"，而这正是本任务的核心。用它来生产核心数据是南辕北辙。**

### 路线 B：先渲染、后写实（**推荐主干**）

1. 采样 SMPL-X：`β`（体型，覆盖全部 BMI 档）、`θ`（姿态）、相机
2. **渲染几何**：mesh → `normal` / `depth` / `part_onehot` / `human_mask` / `contact`
   → **这些都是精确 GT，零误差、零标注成本**
3. 固定每个身份的**外观**（服装纹理、肤色、发型、面部）
4. 渲染 `I_s`（姿态 P_s）与 `I_t`（姿态 P_t），**身份与服装完全一致**
5. 可选：用**结构条件化的写实增强**（深度/姿态 ControlNet + img2img）把渲染图变照片级

**优势**
- ✅ 配对完美：只差姿态
- ✅ 几何精确：渲染得来，不是拟合来的
- ✅ **体型分布完全可控**——包括真实世界里根本采集不到的高 BMI
- ✅ 规模无上限

**代价**
- ⚠️ 需要渲染管线与外观系统（项目已有 SMPLest-X + nvdiffrast + 3DPW 资产）
- ⚠️ **写实增强步骤会让几何漂移**，必须验收（见第 6 节）

### 路线 C：真实数据 + AI 编辑改体型（**作为补充**）

取真实配对数据（iPER / 3DPW），用编辑模型（如 Qwen-Image-2.1、FLUX Kontext）**只改体型**，保持姿态/服装/背景。

- ✅ 真实外观、真实姿态、真实背景
- ✅ 直接产出"同一张图、不同体型"的对照，正是最难的场景
- ⚠️ GT 本身是模型产物，带模型伪影
- ⚠️ **编辑模型很可能顺带改掉姿态或身份**——我们已经在单人实验里观察到这个失败模式
- 参考先例：ChangeLing18K（WACV 2026）正是这么做的：FLUX.1-dev + PuLID 保身份，再用掩码+统一缩放粘贴消除背景与尺度变量

### 三条路线对比

| | 配对性 | 几何精确 | 体型可控 | 真实感 | 结论 |
|---|---|---|---|---|---|
| A 纯文生图 | ❌ | ❌ | ❌ | ✅ | **不用** |
| **B 渲染优先** | ✅ | ✅ | ✅ | ⚠️ 需增强 | **主干** |
| C 真实+编辑 | ✅ | ⚠️ 需拟合 | ✅ | ✅ | **补充** |

## 5. AI 应该介入哪里 —— 一句话原则

> **让 AI 负责"看起来真"，让参数化模型负责"结构正确"。**

| 交给 AI | 必须由参数化模型决定 |
|---|---|
| 皮肤/布料纹理、褶皱、光照 | **身份**（β 决定了骨架与体型） |
| 头发、面部细节 | **姿态**（θ 决定了骨骼） |
| 背景、场景氛围 | **体型**（β 的 shape 分量） |
| 把渲染图变照片级 | **相机**、**几何条件** |

**理由**：GT 必须**自洽且可精确标注**。一旦让 AI 决定体型，你就失去了精确的 β——几何标注从"渲染"退化成"拟合"，误差直接进入监督信号，而监督信号的精度就是模型的上限。

## 6. 质量门控（必须可自动化）

每条样本入库前逐项校验：

| 门控 | 判据 | 为什么 |
|---|---|---|
| 身份一致 | `cos(face_embed(I_s), face_embed(I_t)) > 0.7` | 防止配对时张冠李戴 |
| 体型一致 | 从 `I_s`、`I_t` 分别拟合的 β 之 L2 距离 < 阈值 | **这是本任务的核心不变量** |
| 服装一致 | 衣物区域颜色直方图距离 < 阈值 | 防止模型学会"换衣服" |
| 几何对齐 | 渲染轮廓与写实增强图的轮廓 IoU > 0.9 | 抓写实增强步骤的漂移 |
| 背景受控 | 同一 pair 背景一致（或明确标注为"变背景"样本） | 否则指标被背景主导 |
| 无第三人 | 前景连通域计数 = 1 | 排除杂人污染 |
| 源图可读性 | 记录朝向角、遮挡比、人体占比、轮廓宽高比 | **分层采样的依据，也是失败归因的依据** |

**最后一条尤其重要**：如果不记录源图可读性元数据，将来出现失败就无法归因——就像我这次花了好几轮才定位到 hard_01 的真正原因是源图侧视。

## 7. 建议的规模与构成

| 组成 | 规模 | 来源 | 作用 |
|---|---|---|---|
| **合成主干** | 3,000 身份 × 5 源视角 × 4 目标姿态 ≈ 60k | 路线 B | 精确几何 + 全覆盖 BMI |
| **真实补充** | iPER（已有）+ 3DPW（已有） | 路线 C / 视频 | 真实纹理与背景 |
| **写实增强版** | 对合成主干做增强，双版本并存 | 增强模型 | 缩小 sim-to-real |
| **测试集（身份留出）** | ~3k | 主干划分 | 常规泛化 |
| **测试集（体型留出）** | ~2k，BMI>35 / <17 | 主干划分 | **专门验证体型迁移** |

分辨率建议 **≥768**（与当前管线一致），512 会限制手脸细节的评估能力。

## 8. 与现有资产的衔接

项目已经有的、可直接复用的部分：

- `add/tools/SMPLest-X` — SMPL-X 估计与网格生成
- `add/tools/nvdiffrast-main` — 可微渲染，用于出法线/深度/部位图
- `datasets/iPER/iper_assets_512_nvdiffrast` — 已经是按这套思路渲染过的 iPER 资产（`normal_512` / `part_512` / `depth_npy_512`），**它就是路线 B 在 iPER 上的既有实现**，可以作为管线模板
- `add/data/3DPW`（53,796 帧）— 真实野外全身
- `src/evaluation/dwpose_onnx` — 关键点，用于验收与指标

**也就是说：路线 B 的管线你基本已经有了，缺的是"可控体型采样"和"写实增强"两环。**

## 9. 最小可行起步（如果不想一次做全）

1. **先只做体型这一维**：从现有 SMPL-X 资产里，把同一个人的 β 替换成高 BMI 的 β，重新渲染。**不自建外观系统，改用现成的 iPER 纹理。**
2. **加一条采样规则**：同一身份同一目标姿态 × 多源视角（第 3.3 节）。这条几乎零成本，但直击 hard_01 的失败根因。
3. **先不做写实增强**：用渲染图训练，看体型保持能不能起来。**如果能，再投入增强；如果不能，说明问题不在真实感，增强也救不了。**

这个起步方案能在**不引入新依赖**的前提下，验证整套思路最关键的两个假设。我建议从这里开始。
