实验对象：tiktok_v65_face_overfit_00001 及其生成对照 tiktok_v65_pure_inference　·　 序列 00001，源帧 0014 → 目标帧 0074　·　V6.5 独立 Face 分支，200 步单样本过拟合
评测时间 2026-09-23 20:55–21:08 只读评测，未改动任何训练产物 离线 + 单步前向 + 28 步生成三重验证 评测器：ArcFace / LPIPS / Landmark

客观结论（先看这一条）

该实验在“训练点单步指标”上成立，但在“真实多步生成”上不成立，且方向是负面的。 32 步真实采样中，开启 Face 分支后——身份相似度下降、LPIPS 变差、关键点误差变大，人脸区域出现肉眼可见的崩坏伪影。 成因已定位：Face 分支只在单一时间步（t=150）被训练，却在 t<650 的整个区间都被激活， 在未训练区间的输出是有害的。

一、实验配置与评测口径

实验设置（实测确认）

  • 数据：TikTok 序列 00001，同序列同一人。源帧 0014（索引 13）→ 目标帧 0074（索引 73）
  • 分辨率：原生 604×1080 直接各向异性拉伸到 512×512（align_mode="resize"，非等比裁剪）
  • 训练：200 步，固定时间步 t=150（σ=0.15），单步去噪监督，耗时 64 s
  • 可训练参数仅 3 组：zero_heads_and_gate（13）、face_encoders（149）、face_attention_and_adapters（79）
  • 人脸框（归一化）：源 [0.241, 0.109, 0.625, 0.494]，目标 [0.244, 0.201, 0.557, 0.514]

必须说明的两个前提

① 身份参照本身有差距。源帧与目标帧的 ArcFace 余弦相似度为 0.7313， 落在该序列全部帧对分布的中下位置（均值 0.783，p05=0.634，p95=0.943）。原因是舞蹈动作带来的姿态差异。 这意味着“与源帧人脸”的可达上限本来就不是 1.0。

② 监督信号与被评参照是同一张图。训练用的 target_crop 与验证用的 target_crop 都取自目标帧 0074 的人脸像素——训练集即测试集。 这是单样本过拟合实验的固有性质，因此它只能证明“可拟合”，不能证明“学会了泛化”。

三条必须指出的问题：
  1. 指标饱和。未训练的 step 0 的 FaceSim 已经是 0.976。原因很直接：σ=0.15 时 noisy = 0.85·target + 0.15·noise，输入里已含 85% 的目标帧信息，单步 x0 估计天然接近答案。 这是输入泄漏，不是模型能力。可提升的区间被压缩在 0.019 之内。
  2. 非单调。FaceSim 峰值在 step 75（0.99471），随后回落到 step 200 的 0.98825。 也就是说“训练越久越像目标帧”并不成立，末步不是最优快照。
  3. 身份方向没有改善。与源帧人脸的身份相似度：基线 0.79328 → 末步 0.78842（−0.5%）。 峰值也仅 0.80188（+1.1%）。Face 分支让生成向“目标帧的像素”靠拢，但并没有让身份更接近源人物—— 这与“身份保持的姿态编辑”这一任务目标不是一回事。
唯一明确的正向证据：空间选择性良好。ON 与 OFF 的差异，在 ROI 内的单位强度是 ROI 外的 28.3 倍（ROI 内 MSE 3.68e-4 vs ROI 外 1.26e-5）。按总面积计，ROI 只占 9.8% 却承载了 75.5% 的差异。 说明该分支确实“只动脸”，没有全局污染。（此前基于 latent 空间 outside 指标提出的“泄漏担忧”， 在像素空间按精确 box 重测后应下调等级。）

四、第三层证据：时间步扫描 —— 定位成因

我怀疑问题出在 训练与推理的条件不匹配。检查强度调度后发现关键事实： Face 分支的生效窗是 progress ∈ [0.35, 1.0]，即 t < 650 的每一步都会介入， 而训练只在 t=150 一个点上做过。中间是一整片“注入但从未训练”的区域。

交叉验证成立。我在 t=150 重跑得到 LPIPS OFF/ON = 0.02805 / 0.01509， 而实验记录（step 200）为 0.02873 / 0.01510——ON 值几乎完全重合。 FaceSim 也吻合（0.97918/0.98743 vs 0.97859/0.98588）。这既验证了我的复现链， 也独立证实了实验日志本身是可信的。
成因确认：训练—推理条件不匹配（train/inference mismatch）。
  • 训练只覆盖 1 个时间步（t=150，σ=0.15）；
  • 推理时 Face 分支在 t<650 的全部 ~18 个采样步上激活（σ 从 0.64 一路降到 0）；
  • 7 个测点中，只有 t=150 一个点给出明确改善；t=250/350/450 三个点明确恶化，其中 t=350 的 ΔLPIPS 达 +0.01682；
  • 多步采样必然经过这些“未训练点”，伤害沿途累积，最终体现为生成图的可见崩坏。

按优先级排列的修改建议

  1. （最高）改为多时间步训练。把 fixed_timestep 换成在 [0, 650] 上采样， 或至少覆盖 progress∈[0.35,1.0] 对应的 σ 区间。这是当前负结果的直接成因，改起来最便宜。
  2. （高）引入跨帧 / 跨人的验证集。训练与评测用同一帧导致无法区分“学会迁移”与“记住这一帧”。 建议同序列换帧对（如 0014→0060）复测，观察指标是否保持。
  3. （高）把“与源帧身份相似度”纳入主判据。当前监督只指向目标帧像素， 导致分支优化的是“像目标帧”而非“保源身份”，与任务目标存在系统性偏差。
  4. （中）收紧 Face 调度窗。既然 t=250~450 区间有害，可把 start_progress 从 0.35 提到 0.7 附近，让分支只在低噪声端介入，先验证伤害是否消失。
  5. （中）修正 604×1080 → 512 的对齐方式。当前 align_mode="resize" 属各向异性拉伸 （纵向压缩约 1.79 倍），人脸几何被扭曲，会同时污染训练与评测。建议改为 square_crop 或等比缩放。
  6. （低）修掉单步指标的口径陷阱。单步 x0 结果建议只作调试参考， 不写入结论性文档——包括本工作区此前引用“face 分支有效”的报告，都应以本次的 28 步证据为准。

本次评测的局限（明确声明）

  • 单样本、单序列、200 步训练。所有结论不构成对 V6.5 Face 架构本身的否决， 只说明“该配置 + 该训练方案”在真实生成链路下无效。
  • ArcFace 在 512 分辨率、姿态差异大的生成图上不够稳定：gen 图与源帧的相似度仅 0.42， 但视觉上确为同一人。因此生成图上的 绝对 身份数值意义有限，ON/OFF 相对比较仍然有效。
  • 时间步扫描是单步前向，不是多步采样。它定位的是“逐点即时效果”， 与最终生成质量之间是因果关系而非等价关系。
