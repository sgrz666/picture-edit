# 高清实拍人物：A/B/C 姿态迁移数据集调研

核查日期：2026-10-03。依据为官方项目页、数据说明、仓库和论文；另查看了 FreeMan 论文中的实拍样例图。本轮未取得受限数据包，未验证候选数据的训练效果。

## 1. 任务定义与结论

用户需要：A 是外观来源，B 是另一人物的姿态参考，C 保留 A 的身份、衣服和体型，采用 B 的姿态。**A 与 B 可以体型不同；不需要 A 本人发生体型变化。** 因此，体型变换数据不能代替姿态迁移数据。此前 9 月 27 日报告讨论的“同一人显著变胖变瘦”不是本次任务的必要条件。

目前最值得取样的三个方向：

- **FreeMan**：真实日常环境，先检查人物像素尺寸，适合验证背景、光照、落地关系。
- **DNA-Rendering 的 Part 1/2**：高分辨率实拍、现成 SMPL-X，适合先接通几何控制与身份保持。
- **MVHumanNet++**：人物和日常衣服数量大，适合扩大外观与体型覆盖；公开图片缩小和背景处理需要特别核查。

这是依据数据形式做出的适配判断，不是模型效果结论。已核查候选均未提供符合本任务定义的现成严格 A/B/C 配对；真实 A/C 可以来自同身份、同衣服的视频，跨人物 B 需要另外检索与筛选。

## 3. 对前三个候选的具体判断

### FreeMan：场景最贴近日常照片

官方样例覆盖室内阅读、户外活动、球场等，人和环境是一起拍摄的。已查看的样例里能看到自然的地面、阴影与物体遮挡，也有部分标定板、布置的道具和远距离小人物。**实拍不等于每帧都适合作为高清人像监督。**

同一 session、同一相机的两帧适合构成 A/C。该数据的相机在不同 session 会重新摆放；不可跨 session 随意配对后假定背景与机位一致。SMPL 是拟合的粗人体标注，不能直接称为精准 SMPL-X。

获取：签署数据使用协议、提交申请表，再申请 HF/OpenXLab 权限。先申请和取少量序列即可。

来源：[官方申请步骤](https://wangjiongw.github.io/freeman/download.html)、[采集及拟合说明](https://arxiv.org/html/2309.05073v4)。[本轮查看的实拍样例](https://arxiv.org/html/2309.05073v4/Scenes1.png)是论文拼图，不是原始 1080P 单帧，也不是模型输出。

### DNA-Rendering：高清和几何标注最容易结合

建议先看 Part 1/2，并明确选高分辨率相机。棚拍的衣服、脸、头发和皮肤来自真实相机图像；数据集名称里的 Rendering 不表示其监督 RGB 全是合成人。它的自然背景多样性仍然不足。

SMC/HDF5 按演员与表演序列组织。目标相机的 RGB 与标注需要按同一 camera/frame 对齐。Kinect 深度分辨率较低且视角不同，不能直接当作 4K RGB 的逐像素深度；需要标定变换，或另用 SMPL-X 渲染几何控制。

获取：官方要求签署协议、使用机构邮箱申请链接；Part 1 约 192GB，Part 2 约 2.2TB，宜先选少量案例。

来源：[数据及标注格式](https://dna-rendering.github.io/inner-download.html)、[采集系统](https://dna-rendering.github.io/inner-details.html)。

### MVHumanNet++：数量优势明显，背景不符合“原始日常场景”的全部要求

采集内容是真人和日常衣服，但场地是室内多视角棚。官方 README 明确说明公开图片缩小到原尺寸一半，并遮掉部分背景。因此应实测拿到的 JPG 尺寸与人物高度，不能把论文采集规格当成下载包规格。

公开 README 的 Part 1/2 状态为约 4000 身份、8000 套衣服；4500/9000 是总体规模。++ 的法线与深度经过估计、重建处理，不应标成传感器测得的精确真值。它更适合作为人物外观与几何训练数据，日常背景能力需搭配另一来源。

获取：填写官方表单获取链接；100 套衣服的样本也走申请入口。

来源：[公开包结构与状态](https://github.com/GAP-LAB-CUHK-SZ/MVHumanNet/blob/main/README.md)、[++ 标注来源](https://kevinlee09.github.io/research/MVHumanNet++/)。

## 4. 中国人物需求：目前能确认到什么程度

FreeMan、MVHumanNet++ 都是国内团队开展的实拍项目，值得优先核对参与者信息。但已读的官方说明未给出中国国籍占比，不能据团队所在地或面部外观宣称“全部中国人”。

DNA 官方公布的演员分组比例是亚洲、白人、黑人、拉美裔约 4:3:2:1，即亚洲组约 40%；亚洲不等于中国国籍。它有中文动作与服装描述，这也不等于人物都来自中国。[官方人口分布说明](https://dna-rendering.github.io/inner-details.html)

如果“中国人物为主”是后续硬要求，需要供应方的采集说明或参与者元数据确认；目前候选的国籍数量标为未知。HumanVid 的真实视频来自全球 Pexels，也没有已核实的中国人物占比。

## 5. 怎样构建 A/B/C，避免错误监督

1. **先构建真实 A/C。** 同身份、同衣服、同 session、同视角取不同姿态帧；检查相机、背景、脸、衣服是否一致。C 必须保留原始相机 RGB。
2. **再找不同身份 B。** 按局部关节旋转、朝向和姿态检索与 C 接近的参考帧；记录姿态距离。只匹配动作名称不足以保证姿态相同。
3. **区分配对强度。** B/C 只是近似相似的配对，不能标成严格真值。严格跨人物、跨体型且姿态精确对应的实拍 C，通常需要另行采集或确认已有同步动作数据；本轮未找到可以直接保证这一点的发布包。
4. **明确保留谁的体型。** 几何重定向应保留 A 的 shape/betas，采用 B 的关节姿态，再处理根位置与机位。直接使用 B 的深度、法线和人体轮廓会带入 B 的体型。
5. **训练和推理边界一致。** 同人 A/C 的目标几何监督可以用于学习姿态控制，但不能将这种训练直接描述成已验证的跨身份 B 重定向。跨身份能力需单独留出测试。

上述为本项目构建建议，尚未实现候选数据 loader。C 的 RGB 和真值掩码只用于训练监督/评测；它们不进入推理生成入口。

## 6. 高清样本的筛选与测试方法

建议保留原始分辨率，并为每张候选记录：原图宽高、人物 bbox 宽高、脸部像素尺寸、运动模糊、遮挡、脚部截断、机位变化、标定板或水印。不要用超分放大代替原始清晰度。

用于本项目的初始门槛建议：

- 512 调试样本：人物高度优先至少 512 像素；源图和目标图共用坐标变换，保留双帧人物范围。
- 1024 高清样本：优先人物高度至少 1024 像素，脸部和服装细节另行目检；这是筛选建议，候选保留率尚未测量。
- 训练、验证、测试按身份隔离；B 参考身份也应遵循划分，避免相邻帧或演员泄漏。

使用顺序建议：先各抽少量序列，出至少 30 组原图 A/B/C 图板，逐例标注 B/C 姿态距离与配对是否严格；确认观感和控制对齐后，再做一个单样本过拟合与少量留出推理。512 过拟合结果只证明链路可用，不作为高清质量验收。

## 7. 次级候选及为何暂缓

| 候选 | 核查结果 | 暂缓原因 |
|---|---|---|
| PKU-DyMVHumans | 1080P/4K 多视角实拍，32 人、45 场景；有多人互动；HF/百度渠道 | 以舞蹈、武术、运动、时装表演为主，未见官方提供 SMPL-X；可留作双人或复杂动作补充。见[官方项目](https://pku-dymvhumans.github.io/)、[数据卡](https://huggingface.co/datasets/zxyun/PKU-DyMVHumans) |
| ActorsHQ | 160 个高清视角，官方相机示例为 4112×3008 | 人物数量小、棚拍；更适合细节和多视角检查。见[官方仓库](https://github.com/synthesiaresearch/humanrf) |
| WPose / UniHuman | 2304 组测试配对；人体裁剪长边处理到 1024 | 偏跨身份重姿态测试；处理到 1024 不保证原始人体清晰度，也不能当作严格 C 训练真值。见[官方仓库](https://github.com/adobe-research/UniHuman) |
| Human4K（2026） | 论文称 6M 原生 4K 图像、11 人、SMPL-X | 论文写明录用后发布；未核实可用下载包，另含合成衣服增强，暂不列可立即使用的主数据。见[论文](https://arxiv.org/html/2607.13646v1) |

HumanVid 仅考虑 **Pexels 真实视频部分**。官方 HF 新上传的部分是合成数据，不应因“1080P”再次把它当实拍。真实部分提供 URL 与相机，原视频需从 Pexels 取得，官方已说明部分测试链接失效。[官方仓库数据说明](https://github.com/zhenzhiwang/HumanVid)
