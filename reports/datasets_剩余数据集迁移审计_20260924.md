## 3. 关键技术发现

### 3.1 13,386 个绝对路径软链集中在 `Hi4D_pilot_v1`

此前记录为「`datasets/` 含 13,386 个绝对路径内部软链」，实测**全部位于 `Hi4D_pilot_v1`**。样例：

```
Hi4D_pilot_v1/final_assets_native_v1/pair16/talk16/cam16/dwpose/A/000085.npz
  -> /home/shangguanrz/project/pic-edit/datasets/Hi4D_pilot_v1/native_interaction_v2/dwpose_native/pair16/talk16/000085_A.npz
```

**这反而是软链回填法依然成立的原因**：这些软链写死的是**原路径**，而迁移后原路径变成软链 → 一次额外跳转后仍解析成功。因此 `Hi4D_pilot_v1` **可以被安全迁移**，无需触碰这 13,386 个软链。

### 3.2 `iPER` 有 13,860 个硬链接

必须使用 `rsync -aH`，否则这些硬链接会被展开成独立副本，**体积膨胀**。同时 `iPER` 是 5 个训练入口脚本的依赖对象（`train_iper_v6_native/detail`、`train_iper_v65_face`、`train_iper_v66_hand`、`eval_iper_v6`）。

### 3.3 `TikTokDataset` 的迁移代价与体积不成正比

522,084 个文件只占 104 G，即**平均 200 KB/文件**（小文件为主）。

- 构建数据集索引：**与文件数成正比**，不是与体积成正比
- 全量 sha256 校验：522k 次 `open+read+hash` 系统调用，在 HDD RAID 上受寻道支配
- 对比参照：`Hi4D-origin` 359 G 只有 34 个文件，单侧哈希 10.5 分钟；`TikTokDataset` 体积只有其 29%，文件数却是其 **15,355 倍**

**预估**：`rsync` 阶段 1~2 小时，哈希校验阶段 2~4 小时，合计**半天量级**。而 `Hi4D-origin` 全程只要 35 分钟。

### 3.4 `TikTokDataset` 正在活跃开发

今日 12:02:05 刚写入 306 张 `TikTok_v2/qc/borderline/*.jpg`（QC 质检产物）。虽当前无进程占用，但说明该目录**处于活跃生产周期中**，迁移时机不佳。

## 5. 结论与建议

### 明确建议：**不再继续迁移**

理由：

1. **紧急状况已解除**：`/` 从 98% / 34 G 降至 77% / 392 G，392 G 余量对当前工作节奏是充裕的。
2. **收益递减**：剩余全部对象迁走也只降 8 个百分点，且单项最大收益（TikTokDataset 104 G）同时是成本与风险最高的一项。
3. **风险不对称**：`iPER` 与 `Hi4D_pilot_v1` 是活跃训练依赖（合计 49 处代码引用），`TikTokDataset` 正在活跃生产。迁移引入的故障面大于获得的收益。
4. **真正的风险变量不在本项目**：`/` 上剩余约 960 G 属另外 5 个共享账号。若 `/` 再次告急，更可能由他们引起，而非本项目（本项目仅占 `/` 的约 18%）。

### 如果仍要推进

**推荐顺序**：`iPER_sample`（演练）→ `champ_motions_example` → `iPER` / `Hi4D_pilot_v1`（等训练间隙）→ `TikTokDataset`（等 TikTok 收尾）。

方法论与 `Hi4D-origin` 完全一致（四阶段 + 门控删除），但需针对下列差异加固：

| 差异点 | 加固措施 |
|---|---|
| `iPER` 有 13,860 硬链 | `rsync -aH`；迁移后校验硬链计数一致 |
| `Hi4D_pilot_v1` 有 13,386 绝对软链 | 迁移后 `find -xtype l` 必须为 0（软链回填后应全部仍可解析） |
| `TikTokDataset` 有 522k 文件 | 索引构建与哈希改为**分片并行提交**、分批校验；预估半天，需后台长跑 |
| `datasets/` 已被 gitignore | 无需处理 git；但需确认无脚本硬编码 `/` 上的输出路径 |

### 需要单独评估的对象

项目内 **`experiments/`（71 G）** 与 **`model-qwen-edit/`（54 G）** 分别是第二、第三大占用，合计 125 G，**接近数据集总量**。但它们不是数据集：

- `experiments/` 可能含 git 跟踪文件，迁移会影响仓库
- 脚本可能硬编码输出路径，软链回填未必够用

如需继续腾空间，**这两项的性价比可能高于剩余数据集**，但必须先做独立的引用面与 git 跟踪审计。
