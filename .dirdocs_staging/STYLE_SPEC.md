# 目录说明重写标准（人工研究式，禁止脚本生成）

## 0. 背景与读者
- 项目：基于 SMPL-X 几何条件的人物图像姿态编辑研究工程（单流 DiT 基座 Qwen-Image-2.1 / DeepGen-1.0 + 各类姿态 Adapter，数据集 iPER / Hi4D / TikTok / 3DPW / CHAMP）。
- 读者：**一个刚接手项目的人类工程师**。他打开某个文件夹的 `README.md`，读完就要能回答三件事：
  1. **这一层目录是在干啥的**（它在项目工作线里的真实职责，不是"存放文件的地方"这种废话）；
  2. **里面具体做了什么内容**（跑过哪些实验/构建过哪些资产/得出过哪些数字结论，用从文件里读到的真实数值说话）；
  3. **层级是什么**（父目录 → 本级 → 每个子目录分别装什么，子目录之间是什么关系：并列版本？流水线阶段？互不相关的实验？）。
- 现状：仓库里已有 2.5 万个由 `scripts/gen_folder_docs.py` 生成的 `目录说明.md`。用户判定其**毫无可读性**。本次工作**不得运行、不得依赖、不得修改**这些生成文件；可以偶尔参考其中的文件清单，但所有结论必须自己读文件核实。

## 1. 唯一的合格范例（用户本人手写）
参考 `experiments/README.md`（远端路径 `/home/shangguanrz/project/pic-edit/experiments/README.md`）的写法。它的特征，必须照搬：
- 开头一段讲清**职责、更新时间、涉及规模**（例如"全部 34 个实验运行""584 个条件缓存张量"）。
- 用**表格做分类索引**（实验族 / 目录 / 基座架构 / 科学问题 / 里程碑结论），而不是一行一行罗列文件名。
- 逐个条目写：**实验目的 → 实验条件（硬件、数据、超参）→ 核心定量结果（PSNR 25.86 dB、PCK@0.02 98.00% 这类从 `summary.json`/`*.log`/`metrics*.json` 里读出来的真数字）→ 结论/科学发现 → 产物与位置（具体到文件名）**。
- 末尾给**调用路径 / 复现方式 / 注意事项**（例如"condition_cache/ 是共享底层依赖，不可删除"、"根分区紧张时按冷归档规范同步到 /data 后建软链，切勿 rm -rf"）。
- 允许指出历史包袱：哪个版本被哪个版本取代、哪些是冒烟、哪些是权威结果。

## 3. 硬性纪律
1. **禁止脚本批量生成**，禁止把 `目录说明.md` 的句子改写后交差。每个目录都要实际 `ls`、抽样打开文件（配置看 JSON 键、日志看尾部统计、清单看首行+行数、图像看尺寸与个数）。
2. **数字必须实证**：写"120 个 run"就得有依据（`ls | wc -l`、`config.json` 里的 count、`summary.json` 字段）。不确定就写"约"并说明依据来源；**不许编造**。
3. **不得修改任何非 README 的文件**；**不得覆盖已存在的 `README.md` / `目录说明.md` 之外的手写文档**；数据集原始目录（`TikTok_dataset`、`Hi4D-origin`）只新增说明、绝不改动内容。
4. **只写 staging**（见第 5 节），**严禁直接在远端写文件**，由主会话统一同步。
5. 中文行文，术语可保留英文；不要 emoji；不要"值得注意的是"这类空话；长度按目录信息量定，叶子小目录 20 行以内即可，重要目录可 100–200 行。
6. 遇到空目录、纯 `.gitkeep`、符号链接、归档快照，要如实写明（"当前为空，预留作 X 的输出位置"）。

## 4. 范围（写到哪一层为止）
- **代码/文档/配置类**（`src/`、`scripts/`、`tests/`、`configs/`、`docs/`、`reports/`、`vram_lab/`、`patches/`、`third_party/`、`deepgen/`）：**每一级都要写**，直到叶子目录。
- **实验/调研类**（`experiments/*`、`research/*`、`results/*`）：写**实验目录级 + 其阶段/产物子目录级**（一般 2–3 级）。
- **数据/权重类**（`datasets/*`、`models/`、`data/`、`add/*`、`/data/shangguanrz/*`）：写**数据集级 + 版本/资产层目录级**；**编号叶子目录（如 `00001/`、`seq_*/`、单帧目录）不逐个写**，而是在其父目录 README 里用一段讲清"每个编号目录内部布局"（列一份实测目录树 + 文件命名与张量形状）并统计覆盖范围。
- 隐藏目录、`__pycache__`、第三方仓库内部（`add/tools/SMPLest-X/**` 等）只在父级 README 用一行交代性质，不深入。

## 6. 远端访问方式（本机是 Windows + Git Bash）
- 连接：`ssh sg '<单条命令>'`（免密；远端主机 node01，**无外网**）。
- **绝对不要**在 `ssh "..."` 里嵌套多行 `for/do/done` 或 heredoc（会触发语法错误）。需要复杂探查时：把脚本写到本地临时文件（例如 `D:\codeplus\pictureedit\.dirdocs_staging\_probe.sh`），然后 `ssh sg 'bash -s' < .dirdocs_staging/_probe.sh`。注意该临时文件是共享的，多个 agent 并发探查时请各自用唯一文件名 `.dirdocs_staging\_probe_<你的分区名>.sh`。
- 常用：`ls -la`、`find <dir> -maxdepth 1 -printf '%y %s %TY-%Tm-%Td %p\n'`、`du -sh --si`、`head -c 1500 <file>`、`python3 -c "import json;..."`（远端 python3 可用，`jq` 不一定有）、读日志用 `tail -n 40`。
- 大目录统计先 `ls | wc -l`、`find -maxdepth 1 -type d | wc -l`，再抽样打开 2–3 个代表项。

## 7. 汇报格式（回给主会话，控制在 200 字以内）
写完后只汇报：负责的子树、写了多少份 README、跳过哪些已有手写文档、发现的 3–5 条**对全局有价值的事实**（例如某缓存是共享依赖、某目录实为软链归档、某实验结论推翻另一实验）。不要把 README 正文粘回来。
