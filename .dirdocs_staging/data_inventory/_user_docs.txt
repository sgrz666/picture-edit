# datasets/TikTokDataset/ —— TikTok 单人舞蹈数据集（全构建层）

本目录是**软链接**，实体在数据盘：

```
datasets/TikTokDataset -> /data/shangguanrz/pic-edit-datasets/TikTokDataset
```

TikTok v3 处理后的单人舞蹈数据集，是 Qwen 迁移线（qwen21 / qwen21_full）的重要训练源之一。

## 里面有什么

实体（数据盘，逻辑约 110.9 GB）包含多层：

- `TikTok_dataset/`：官方原始图像与 mask（`00001/`…`00342/`，共 342 个序列目录，`images/*.png` + `masks/*.png`）。
- `TikTok_3d_assets_native/`：原生 3D 资产（342 目录），含法线/深度/网格 mask/`v6_conditions.pt` 等。
- `TikTok_v3/`：**当前训练实际使用版**构建层：
  - `dwpose_v1/`（295 序列的骨架可视化与 134 关键点 JSON）
  - `manifests/`（`frame_inventory`、`candidate_pool`、`condition_inventory`、`pairs` 与 `pairs_strict_v1` 配对清单等，27 个直属文件 + 子目录）
  - `qc/`（八类人工/自动质检结果）
  - `qwen21_face_feature_cache/`（每序列一个人脸特征 `.pt` + 索引）
  - `stats.json`：`tiktok_v3_frame_inventory`，**340 序列 / 92,961 帧**
- `splits/`：`split_summary.json`、train/val/test 序列清单（序列级互斥划分，train 179 / val 20 / test 20，共 219 序列）。
- `TikTok_v2/`、`TikTok_Raw_Videos/`、`model/`、`showcase_single/`、`logs/`、`License.pdf`：历史/辅助层。

关键统计（已实测核实）：

- `usable_frame_pool`：**6,909 有效帧**（从 7,481 几何有效帧中 fine_reject 572 得到）。
- `pairs_strict_v1`：**train 8,574 / val 1,120 / test 1,156** 对（同序列内配对、跨划分不配对）。

## 与上下层的关系

- 预处理/配对：`scripts/data/build_tiktok_v3_*`、`fill_tiktok_v3_missing_geometry.py`、`split_tiktok_v3_groupwise.py`。
- 训练准备/入口：`scripts/data/prepare_tiktok_qwen21_training.py`、`prepare_tiktok_qwen21_face.py`；`scripts/train/train_tiktok_v65_face.py`、`train_tiktok_overfit_sanity.py`。
- 训练读取顺序：从 `manifests/pairs(_strict_v1)/<split>_pairs.jsonl` 取 pair，按 `sequence_id` + `source/target_stem` 从 `TikTok_dataset` 取 RGB/mask、从 `dwpose_v1` 取目标骨架、从 `TikTok_3d_assets_native` 取法线/深度/网格 mask/`v6_conditions.pt`。

## 注意与坑

- **两个客观劣势（实测）**：① 原帧尺寸 **604×1080**，resize 至 512 时不是 square_crop 居中裁剪，而是横向压缩约 **1.79 倍**，存在宽高比失真；② 数据**身份未认证**（无身份一致性保证），做 Face-ID 保真度评测时要当心。
- 实体在数据盘，仓库内只是软链；清单里同时写有仓库绝对路径与数据盘绝对路径两种写法，换机器同步软链即可。
- `TikTok_v2/`、`TikTok_Raw_Videos/` 等为历史层，训练勿引用错版本。

# models/Qwen-Image-2.1/ —— Qwen-Image-2.1 基座模型（迁移线）

本目录是 `src/pose_control/qwen21` 与 `src/pose_control/qwen21_full` 两条迁移线的基座扩散模型。它是**软链接**，实体在数据盘：

```
models/Qwen-Image-2.1 -> /data/shangguanrz/pic-edit-models/Qwen-Image-2.1
```

## 里面有什么

标准的 diffusers 模型卡结构（`model_index.json` 声明 `QwenImage21Pipeline`，diffusers 0.37.0.dev0）：

- `transformer/`：Qwen-Image-2.1 的 7B 单流 DiT（`QwenImage21Transformer2DModel`，官方称 32 个 Single-Stream DiT 层）。
- `text_encoder/`：Qwen3VL 多模态文本编码器（`Qwen3VLForConditionalGeneration`）。
- `vae/`：`AutoencoderKLQwenImage21`。
- `processor/`：`Qwen3VLProcessor`；`scheduler/`：`FlowMatchEulerDiscreteScheduler`。
- `assets/`、`README.md`、`LICENSE` 等。

模型支持文生图与图像编辑，并原生支持 RGBA（透明通道）。

## 与上下层的关系

- 被 `src/pose_control/qwen21_full/execution.py:32` 以 `MODEL = ROOT / 'models/Qwen-Image-2.1'` 加载，是 V6 全量迁移（qwen21_full）的基座。
- `src/pose_control/qwen21/`（runtime / body_adapter / face_adapter / dual_adapter）也基于该 32-block 变压器结构做适配器注入。
- 上层数据集：`datasets/iPER/`、`datasets/TikTokDataset/` 经 `scripts/` 预处理后喂给这条线训练。

## 注意与坑

- 实体在数据盘，仓库内只是软链；**不要改软链指向**，换机器时同步改链接而不是改清单里的绝对路径。
- 这是 7B 基座，训练时冻结基座、只训自研适配器（与 DeepGen 线不同，这里没有 `models/DeepGen-1.0-diffusers` 那种 frozen 大包）。

# iper_v6_comparative_3000/ —— 3000 步多阶段横向对照展示

## 实验目的
以每 500 步为一个里程碑保存并生成对比网格，直观展示 V6 适配器在 0~3000 步区间的姿态对齐与画质演变规律，用于横向对照。

## 里面有什么
- 检查点：`adapter_step_500.pt`、`adapter_step_1000.pt`、`adapter_step_1500.pt`、`adapter_step_2000.pt`、`adapter_step_2500.pt`、`adapter_step_3000.pt`（各约 1.59GB），以及 `checkpoint_best.pt`、`checkpoint_last.pt`。
- `eval_results/`：`eval_metrics.json`、逐样本结果与 `images/`。
- `multistage_evolution_showcase/`、`stage_evolution/`：分阶段演变产物。
- `multi_stage_evolution_grid.png`：多阶段演变对比网格。
- 日志：`train.log`、`launcher.log`、`eval.log`、`multi_stage_eval.log`。
- `目录说明.md`（远端既有；本目录为指向归档盘的软链接）。

## 关键结论
来自 `eval_results/eval_metrics.json` 的 summary：50 样本平均 **PSNR 22.30 dB**、**SSIM 0.9583**、**MAE 8.10**。与总矩阵一致（Step500 约 20.58 dB、Step3000 平均 22.30 dB），印证早期快速收敛、后期边际收益递减。

# review_20260908_v2/ —— DeepGen-1.0 显存与架构极限正式复核运行库

## 实验目的
对 DeepGen-1.0（SD3 MMDiT 2.47B）开展严苛的显存基准测绘：覆盖 512/768/1024 分辨率、Direct 缩放 vs Letterbox 填充、条件缓存命中 vs 实时计算，并用 50ms NVML 高频采样显存，验证数值不变量（零初始化门槛、梯度阈值）。当前路径为指向归档盘 `/data/shangguanrz/pic-edit-archive/cleanup_20261003/experiments/review_20260908_v2` 的软链接，磁盘内容一致。

## 里面有什么
- `ACCEPTANCE.json`：验收结论，记录 111 个 primary runs 全部判定 `PASS`（`status_counts.PASS=111`，`reproducible_output_exact=true`）。
- 结论文档：`EXPERIMENT_CONCLUSION.md`、`QUALITY_REVIEW.md`、`MEMORY_REPORT.md`、`RUNBOOK.md`、`QUALITY_REVIEW.md`。
- 量化结果：`results.json`、`scores.json`、`summary.csv`、`quality_manifest.json`、`main_manifest.json` 等。
- `runs/`（122 个子目录）、`logs/`（万级日志）、`configs/`、`cache/`、`review_sheets/`。
- `evidence.zip`（约 212MB 证据包）、`index.html`（HTML Demo 副本，约 12MB）。

## 关键结论
- 111 个主运行用例 100% PASS，零异常退出。
- Letterbox 保持纵横比可显著平抑显存尖峰；Direct 模式在 1024 下显存陡增，确立 **Letterbox 为全项目预处理标准**。
- 零初始化门槛校验与梯度阈值校验 100% 达标，建立 80G GPU 并发容量模型。

## 与其他实验的关系
属于**技术线 1**的"显存与架构极限压测族"正式版，是后续所有 DeepGen 实验的显存安全基线。详见 [../README.md](../README.md) 矩阵。
