## 3. 任务定位与硬约束

- **任务**：在保持身份、服饰、场景一致的前提下，把源图人物 A 的姿态替换为目标动作 B；需支持握手、搭肩、拥抱等双人接触动作并精细到手指结构。
- **任务书硬指标**：生成主干 ≤ 6B 参数；交互姿态合理比例 ≥ 90%；主观质量优于 Qwen-Edit 基线 ≥ 5%。
- **选型**：主干用 **DeepGen-1.0-diffusers** 的 DiT（≈2.47B 存储参数，满足 <6B）；**Qwen-Image-Edit-2511（20B）** 已完成显存可行性分析，定位为质量上界与教师模型。

## 4. 技术架构（当前版本）

```
SMPL-X 图/参数
  → SMPLXConditionInjector → ConditionBundle → SMPLXAdapterReasoner
  → InternalControlState → Geometry / Interaction(/Detail) 独立桥接
  → 动态双/三分支 SharedRecurrentControlCore（每去噪步计算）
  → ControlStrengthController → 6 组 DeepGen 原生残差注入
```

- **适配器**：`UnifiedSMPLXAdapterV6`，总参数 **227.98 M**；方案 A 下达 **169.89 M 可训练 / 58.09 M 严格冻结**。
- **注入方式**：6 组零初始化残差头，对应 DeepGen 24 层中 6 个原生残差组（block 0-3 / 4-7 / 8-11 / 12-15 / 16-19 / 20-22）；block 23 为 `context_pre_only` 不接残差。参考图 token 残差恒为 0，只控制目标 token。
- **分层学习率**（4 组）：Zero Heads & 门控 14.165 M @1e-4（wd 0）；条件编码与推理 31.84 M @5e-5；桥接与身份绑定 5.63 M @5e-5；共享控制核心 118.26 M @1e-5。
- **损失**：掩码加权 Flow-Matching 速度损失，人体区权重 `w_human = 3.0`，归一化保证尺度稳定。
- **V6.4 新增细节分支**（`src/pose_control/v6/detail/`）：`DetailRegion = FACE / LEFT_HAND / RIGHT_HAND`，含 68 点人脸 + 2×21 手部关键点、每人物每部位 1–3 张 224×224 局部外观参考图（`DetailReferenceBatch`，用于绕过 VAE 8× 下采样导致的手脸亚像素瓶颈）、左手镜像 canonicalize；控制核升级为 geometry / interaction / **detail** 三分支共用同一 `shared_block`；`ARCHITECTURE_VERSION = "v6.4"`。
- **冻结边界**：DeepGen Transformer / VAE / Qwen2.5-VL / Connector 全部 `requires_grad=False`；训练时仍以无 `no_grad` 方式前向，使梯度可经残差回流至适配器。

## 6. 实验结论（按证据强度分层）

### 6.1 强证据：图像域定量对比

| 对比 | 样本 | 检查点 | Adapter ON | Adapter OFF | 差值 |
| --- | --- | --- | --- | --- | --- |
| 官方 test 子集 `baseline_50` | 50 对 / 19 身份（⊆ test） | `step_12000` | PSNR 24.28 dB / SSIM 0.9759 / MAE 6.91 | 17.35 dB / 0.8733 / 16.06 | **PSNR +6.94 dB，MAE −57%** |
| dev_val | 50 对 | `step_20000` | PSNR 24.00 dB / SSIM 0.9811 / MAE 6.15 | 16.93 dB / 0.9005 / 14.36 | **+7.07 dB** |
| 3k pilot 对照 | 同 baseline_50 | `step_3000` | PSNR 22.30 dB / SSIM 0.9583 / MAE 8.10 | — | 20k 相比 3k **+1.98 dB** |

结论：几何控制分支在最终生成图像上产生了实质、可复现的差异，且 20k 明显优于 3k。

### 6.2 全量 20k 训练（`experiments/iper_v6_native_20k_v1`）

- 耗时 **19.29 h** 完成 20,000 optimizer steps；峰值显存 **16.50 GiB**（预留 16.91 GiB）；单 micro-step 约 0.4–2.0 s。
- 末次验证：**ON 0.2276 / Weighted 0.2484 / OFF 0.2454 / Perturbed 0.2379**。排序 ON < Perturbed < OFF 方向正确，但 **ON 相对 OFF 仅优 7.2%**，远低于计划书设定的 ≥30% 门槛。
- 关键解释：验证损失在**未配对的随机噪声/时间步**上计算，高噪声步所有预测趋同，因而系统性低估控制效果——这与图像域 +6.94 dB 的巨大差异是一致的。**不能把流匹配验证损失当作姿态敏感度判据。**
- 检查点：目录内 9 个 `.pt`（每个 1.59 GB，合计约 14 GB）；`checkpoint_best.pt` 只在 4k/8k/12k/16k/20k 五个保存点中选优（best = step_12000），**全局最优（step_5000，0.2094）未被保存**。

### 6.3 V6.4 细节分支首轮过拟合验证（`experiments/iper_v64_detail_overfit_024_6`）

- 配置：单样本 `024_6`，1,500 步，**24.65 min**，647.5 ms/step，峰值显存 **15.94 GiB**。
- 完整性校验：非细节参数 SHA-256 训练前后一致（`1571e4ec…`）；细节关闭时 step1500 与 step0 输出 PSNR 51.64 dB → **细节分支对 V6.3 行为零污染**。
- 10 项验收：**6 通过 / 4 未通过**（`all_criteria_passed = false`）。

| 通过项 | 数值 |
| --- | --- |
| 细节残差 RMS 非零、有限、不爆炸 | 0.4979 |
| 人脸 ΔSSIM / ΔPSNR vs OFF | +0.2830 / **+2.97 dB** |
| 手部平均 ΔSSIM vs OFF | +0.0721 |
| 人脸手部以外区域 PSNR 退化 | −0.54 dB（无退化） |
| 峰值显存 < 24 GiB | 15.94 GiB |

| 未通过项 | 实测 | 门槛 |
| --- | --- | --- |
| 末 50 步总损失 / 初始 | 57.94% | ≤30% |
| 人脸 flow MSE 下降 | 55.92% | ≥60% |
| 左手 flow MSE 下降 | 50.71% | ≥60% |
| 右手 flow MSE 下降 | 51.62% | ≥60% |
| 手部 PCK@0.1 | **0.143**（Δ +0.083） | ≥0.70 且 Δ ≥ +0.10 |

判读：细节分支在**像素相似度**层面明确有效（人脸 +2.97 dB 是很大幅度），但**手部关键点几何精度严重不足**（PCK 0.143），即「看起来更像」但「关节点没对上」。四个未通过项集中在同一方向：收敛幅度不够。

## 7. 风险与阻塞项

1. **磁盘（高）**：系统盘 98%、仅剩 46 GB。9 个 20k 检查点已占 14 GB，V6.4/Hi4D 双人训练再开将迅速吃满；`CheckpointManager` 的滚动保留策略必须严格执行。
2. **验证判据（高）**：现行流匹配验证损失对控制效果区分度不足（ON/OFF 仅 7%），却曾作为 gate。应改为**固定噪声/时间步的配对评估**，或以人体区域 PSNR/SSIM + pose PCK 作为主判据。
3. **手部几何（高）**：PCK@0.1 = 0.143 距任务书「精确到手指结构」的要求差距很大，是当前最明确的技术缺口。
4. **共租户争用（中）**：`lileiteng` 的排队作业在 GPU0 空闲 ≥50 GB 时自动启动（当前条件已满足）。我方 16.5 GiB 训练仍可并存，但双作业叠加后余量有限，且对方可能抢占调度。
5. **Qwen-Edit 对比缺失（中）**：任务书要求「主观质量优于 Qwen-Edit 基线 5%」，目前**只有一张定性图**（`experiments/qwen_edit_results/qwen_edit_single_result.png`），**无任何定量对比**，是验收硬性缺口。
6. **几何指标盲区（中）**：全图 PSNR/SSIM 受白背景主导，对手/脸小区域近似「盲」。需补人体区域指标与姿态 PCK。
7. **文档漂移（低）**：本地 `STAGE_SUMMARY_FOR_AGENT.md`（2026-09-12）仍描述旧 8 通道 `PoseConditionAdapter`（172.77 M）与只做过 iPER 单样本切片，已与 V6.3/V6.4 现状脱节；`src/adapter/pose_adapter.py` 类内容亦属旧版。
8. **工作区未提交（低）**：远程 `main` 有 4 个已修改文件（`eval_iper_v6.py`、`src/pose_control/v6/detail/preparer.py`、`tests/test_condition_injector_v1.py`、`outputs/deepgen_control_interface_smoke_dual.json`）与大量未跟踪脚本（`scratch_*`、`build_hi4d_*`、`run_hi4d_dual_overfit.py` 等），HI4D 数据构建链路尚未入库。
9. **展示链路不稳定（低）**：TikTok 展示批处理 8 选 4 失败，原因统一为 `TikTok_3d_assets_native/{00003,00004,00005,00007}/depth_vis` 目录缺失（数据侧缺件，非代码缺陷）；iPER 展示 8/8 全部成功。

## 8. 建议下一步（按优先级）

1. **先解决判据问题**：把验证改为配对（固定噪声 + 固定时间步）评估，并在人体区域上计算 PSNR/SSIM 与 pose PCK，以此重新判定 V6.3 是否达标——现有 7% 的数字很可能只是度量缺陷。
2. **补 iPER 细节数据源**：重跑高分辨率 DWPose 以获得 68 点人脸 / 2×21 手部 / 103 维 smplx_detail，否则 V6.4 只能在 Hi4D 上训练。
3. **攻手部几何**：PCK 0.143 是最大技术缺口；可考虑提高局部参考图分辨率、加大手部损失权重、或引入独立手部 adapter（与用户此前提出的「face/LH/RH 三条独立流 + 真 Face-ID 网络」设计图方向一致）。
4. **启动 Hi4D 双人过拟合验证**：数据已就绪（2,740 对、QC 0 缺失），但需先确认 Interaction 分支的自监督信号与人物对应关系建模方案。
5. **补 Qwen-Edit-20B 定量对比**：这是任务书硬性验收项，且目前完全空缺。
6. **资源与工程卫生**：清理系统盘（合并/减少检查点、迁移大文件到 22 TB 数据盘）；把 V6.4 与 Hi4D 链路提交入库；更新本地过时交接文档。
