### 移动脚本时必须一并处理的关系

大量入口用 `Path(__file__).resolve().parent` 认定项目根。移动到 `scripts/train/foo.py` 后，根目录定位会变；仅 `git mv` 会破坏模型、数据和日志路径。应统一 ROOT 获取或以包/模块方式启动，不把目录层数写死在所有文件里。

还要检查根脚本互相导入、tests 按文件加载入口、subprocess 构造入口路径、manifest 中的源码哈希路径、Shell 的当前工作目录。比如 Hi4D 训练记录会从 `ROOT / 'train_hi4d_qwen21_dual.py'` 读取源码哈希，迁移时要一起更新这项，而不仅是 CLI。

Git 只适合管理自有源码、清单、规范和小型证据。当前 `/add/` 整体被忽略，连自有数据 reader 和 126 个工具脚本都未纳入主仓库；未来应选择性纳入这些代码，继续排除环境、权重、原始数据与大输出。不能直接 `git add -A`，也不能默认把已有文档删除和整理改动混成一次提交。
