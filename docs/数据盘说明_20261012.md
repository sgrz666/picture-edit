## 二、pic-edit-datasets/（463G）

仓库 `datasets/` 下两个软链指向这里。

### Hi4D-origin/（359G，32 个 tar.gz）

Hi4D 官方原始压缩包，**未解压**——按 pair 分包（`pair00_1` / `pair00_2` / `pair01` … `pair28`，多数约 15G/包），附 `hi4d_urls.txt` 与 `hi4d_files.txt`（官方下载清单）。全解压约 445GiB 但 frames 占 81% 不使用，训练真正需要的是约 85GiB 的几何与标注部分；解压与配准产物在仓库侧 `datasets/Hi4D_pilot_v1/`。注意 Hi4D 是 SMPL（非 SMPL-X，无手脸标注），与主线的 SMPL-X 口径不同。

### TikTokDataset/（105G）

单人舞蹈数据集的**全构建层**，按处理阶段分层：

| 子目录 | 体积 | 内容 |
|---|---|---|
| `TikTok_dataset/` | 48G | 抽取的视频帧序列（`00001`、`00002`… 按序列编号） |
| `TikTok_3d_assets_native/` | 39G | native 分辨率 3D 资产（每序列一套：几何/条件/标注） |
| `showcase_single/` | 16G | 单人 showcase 切片（`sample_01_00001_0014_to_0074` 等，按起止帧命名） |
| `TikTok_Raw_Videos/` | 2.5G | 原始 mp4 |
| `TikTok_v3/` | 761M | **v3 正式构建层**：`manifests/`（401M，配对清单）、`dwpose_v1/`（275M，DWPose 关键点）、`qwen21_face_feature_cache/`（58M，面部特征缓存）、`qc/`（29M，质检）、`stats.json`（340 序列 / 92961 帧统计） |
| `model/` | 665M | TikTok 处理自用模型（内含 `model/` 子目录） |
| `TikTok_v2/` | 252M | v2 旧构建层（历史保留） |
| `splits/` `logs/` | 24K / 3.7M | 划分文件与构建日志 |

v3 的配对口径：340 序列 → 有效 6909 帧 → strict_v1 train 8574 / val 1120 / test 1156 对；test 对全程未参与训练与特征提取。两个客观劣势仍在：604×1080→512 的横压 aspect 失真（1.79×，未修）与身份未认证。

## 十、使用注意

1. 本盘与多人共用，操作前 `df -h /data` 与 `du -sh` 确认；删除任何目录前先审计+备份（历史备份均按批次存 `pic-edit-archive/`）。
2. 跨盘迁移用 `rsync -aH --numeric-ids`，完成后按 `MANIFEST.txt` 式清单抽验 sha256——`tiktok_verify.log` 为空反例说明「跑了校验」≠「留下证据」。
3. 数据集原始包（Hi4D tar、TikTok 帧）不可再生，只读使用；处理产物放仓库侧或实验区，不要原地覆盖原始层。
