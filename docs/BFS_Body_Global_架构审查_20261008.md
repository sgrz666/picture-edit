# BFS Body + Global Adapter 架构审查（2026-10-08）

结论：冻结 Qwen、冻结可开关 BFS、训练几何 Adapter 的组合有研究价值。对全身人物重定向，Body 是直接相关的候选任务先验；目前没有证据证明它能直接改善现有几何条件链路，也不宜同时更换控制架构和训练数据。优先复用现有 Qwen Full Adapter，单独验证 BFS，再决定是否引入更大的 ControlNet。

本次审查读取了用户提供的完整架构方案、sg 上实际 Body 权重和现有桥接代码、安装的 Qwen 2.1 pipeline/transformer 源码，并核对 BFS、VideoX-Fun、Parts2Whole 的公开说明。没有启动模型加载、生成或训练，没有修改正式模型、训练配置或现有控制代码。

## 2. 方案中可以采用的部分

- Qwen 和 BFS 固定，只训练几何控制模块。冻结参数仍需保留损失经 DiT 回传到 Adapter 的计算图。
- 将源人物外观与目标几何分别作为条件；BFS 可开关，原始 Qwen 保留为基线。
- 只对目标图 token 添加控制残差，保持参考/文本前缀免于直接的 Adapter 更新。
- 最终残差输出建立一个零边界，避免连续两个严格为零的可训练映射或零门控阻断初始梯度。
- 目标体型与姿态解耦：若 A 的可靠体型参数可用，用 A 的 shape 和 B 的姿态重新渲染所有几何图，同时统一相机、根朝向、平移与画布。
- 按训练预算和测试输入约定做消融，分别检查姿态、身份、衣服、背景和失败率。

这些原则合理，但“BFS 只管身份，Global 只管姿态”仅为功能目标。几何残差经注意力传播后也会影响外观，BFS 也影响姿态和背景。两者不具有硬性的功能隔离。

## 3. 首要问题：两套输入定义

[BFS Body 官方说明](https://huggingface.co/Alissonerdx/BFS-Best-Face-Swap/blob/main/docs/qwen-image-2.1-body.md)规定图 1 提供场景、姿态、光照和背景，图 2 提供人物身份、衣服和体型。其参考训练格式主要是浅色背景、正面站立的全身照；作者建议场景约 2 MP、参考约 0.59 MP，并明确姿态仅近似匹配。

我们当前主协议为 **A RGB + B 几何条件 → 输出**。将 BFS 加到这条单参考链路上，属于新的条件组合实验，不等于已接通它的原生两图工作流。

应分开验证：

| 路线 | 生成条件 | 能回答的问题 |
| --- | --- | --- |
| G：现有主协议 | A RGB + B 几何；分别启用/关闭 BFS | BFS 先验能否改善我们的几何重定向 |
| R：原生 RGB 换人 | 独立场景 B RGB + A RGB，可附加 B 几何 | BFS 与几何控制是否互补于两图换人 |
| C：生成图后处理 | 现有控制生成 C，再给 C + A 做 BFS | 后处理是否能改善外观、是否损伤已有几何和背景 |

G/R/C 不能混成一个“基模替换效果”均值。R 若把监督目标 C 本身当场景图，尤其同人同衣样本，会让复制目标成为捷径。合法的独立 B 应与目标 C 区分，并具有可核验的 A 身份、B 姿态、场景定义。

人体 normal/part 渲染作为 BFS 场景参考可以实验，但它与真实场景照片差异明显，收益待验证。C 路线则受第一阶段质量限制：C 中缺失的 B 表情、头姿不能指望 BFS 自动恢复。

还需明确输出背景来自 A、B 还是独立场景。BFS 的原生约定是保留图 1 场景；方案中保留 A 背景、并编辑源/目标人体并集，属于另一种编辑定义。

## 4. 现有桥接已实现，不能按空白项目估算

sg 的 `src/pose_control/qwen21_full/qwen_adapter.py` 已有：

- Qwen 4096 维 output bridge 与 legacy 几何/身份条件接口；
- 从实际 `img_shapes` 最后一个图块读取目标 token 网格；
- 保留前缀，只对尾部目标 token 添加残差；
- 32 个原生 Transformer block 的逐层 hook；
- **6 组残差，每层选择对应组注入**，并非“8 个单独注入位置”；
- 针对继承 head 是否非零选择初始化，避免双零边界。

首先应沿用这些已有实现。新方案的 8/16 组设计需要同时说明“独立输出头数量”和“实际添加残差的位置数量”，不可当作同一个超参数。

本次也确认当前 Qwen 2.1 VAE 空间倍率为 16、latent 通道为 64，DiT patch_size 为 1，pack 是空间展平。1024 正方形目标对应 64×64、4096 个目标 token；方案这里与当前版本一致。仍应以实际尺寸和 img_shapes 为准，避免引用旧版 Qwen 的 2×2 packing。

Body 未更新 16–23 层，可作为“中段加强几何”的消融候选。但这些层的输入已受前段 BFS 影响，不能据此宣称这些层完全独立或必然最适合控制。

## 5. VideoX-Fun：存在，可参考，暂不优先替换整套架构

[训练指南](https://github.com/aigc-apps/VideoX-Fun/blob/main/scripts/qwenimage21_fun/README_TRAIN.md)、[控制配置](https://github.com/aigc-apps/VideoX-Fun/blob/main/config/qwenimage21/qwenimage21_control.yaml)以及[预训练仓库](https://huggingface.co/alibaba-pai/Qwen-Image-2.1-Fun-Controlnet-Union)确实存在。

配置为 `[0,2,...,30]` 共 16 个控制位置、`control_in_dim=129`。训练指南把条件定义为控制 latent 64 通道、mask 1 通道、masked-image latent 64 通道的联合输入，并说明控制存在时自动关闭 prefix KV cache。

因此它可以作为更大控制网络的独立基线及接口参考，但不是直接接收 SMPL-X 参数、normal、part 的现成替代品。多参考图顺序、目标 token、BFS 的键名与缩放、训练梯度、checkpoint 命名、缓存和显存均须适配验证。

我们已有桥接和数据链路，本阶段同时换 BFS、ControlNet、数据集，会使收益难以归因。优先保留当前控制实现；若姿态控制仍不足，再将这个 16 点控制分支列为下一阶段实验。

## 6. 数据、体型与表情需要补充约束

[Parts2Whole](https://github.com/huanngzh/Parts2Whole)作者说明约 41,500 个参考-目标组合，并提供多部位外观与姿态条件。它是可考虑的新数据来源；本次读取的项目文档仍有 iPER/TikTok 链路，不能把方案的“当前采用 DeepFashion”当作已经完成的数据切换。

同 ID 不自动证明各参数估计可靠。新数据需要核验人物/衣服一致性、SMPL-X 拟合质量、相机与画布对齐、参考格式，以及训练/测试的人物隔离。

`shape_A + pose_B` 只有在 A 的体型估计可用时才能落实。缺少 A shape 时应记录使用统一体型先验，并分别评测外观体型保持；不能承诺由一张源图精确保留三维体型。替换 shape 后应重新渲染 normal/part/mask，避免参数来自 A 而空间图仍来自 B。

用户目标含“表情服从 B”。Global 第一阶段可以暂缓面部细节，但最终需要可靠的 B 头姿、jaw/expression 条件和独立表情评测。Body LoRA 和粗骨架控制本身没有证明这一项已满足。

人体区域乘残差只能约束直接注入的位置。后续全局注意力与解码仍可能改变区域外像素；严格背景保持需要编辑掩码、边界融合或其他显式机制，并报告区域外变化。

## 7. 推荐顺序和验收

1. 固定当前数据、提示词、分辨率、Adapter 结构及 G 协议。先检查 Body 权重完整加载、开关回退、目标/前缀注入边界及梯度；已有 Adapter 热加载 BFS 的结果仅作兼容性观察。
2. 以相同起点和预算，比较原 Qwen 上训练的 Global 与固定 Qwen+BFS Body 上适配训练的 Global。记录训练时是否加载 BFS，推理使用对应底座。
3. 单独建立 R 或 C 的原生两图实验，明确输入、目标身份、场景和 GT 来源；不使用真实 GT 场景复制来证明 G 协议的效果。
4. 稳定后再比较控制层分组、VideoX-Fun 控制基线及 Head/Face 辅助分支。每次只引入可归因的主要变化。

验收包含：未见过的人物、跨人物迁移、侧脸与大幅转身、遮挡、不同服装；多个 seed；身体关键点、三维/二维头姿及表情、A 身份、衣物外观、区域外 MAE、失败覆盖率、时延和显存。需要区分 source-A cosine 与目标头姿，避免身份分数偏好源参考朝向。

[既有扩大实验](BFS_扩大样本对照_20261004.md)是简化 Body 生成后，关闭项目 Adapter 的 Head 二次编辑对照。它支持身份/头姿存在取舍，尚未验证这里的固定 Body LoRA + Global 联合训练设计。
