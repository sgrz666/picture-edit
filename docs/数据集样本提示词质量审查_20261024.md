# TikTok / Hi4D 逐样本提示词质量审查（2026-10-24）

## 1. 审查目的与判据来源

对 `sg` 上两套数据集**每一条样本的提示词**做一次全量质量审查，回答一个问题：
这些提示词是否服务于任务目标，还是只在形式上"像提示词"。

判据取自三处，不另立标准：

1. 合同任务书 `task/人物图像姿态编辑任务书_v3.docx`（经 `task/README.md` 转述）：
   **保持身份、服饰、场景一致**的前提下做姿态编辑；目标②要求**双人接触交互**（拥抱/搂肩）与身份不串味。
2. 两套重写实验自己声明的契约：
   - `experiments/3.singel man/tiktok_pe_prompt_rewrite_20261014/README.md` §3（训练形式禁止图号、禁止指向看不到的目标图）
   - `experiments/4.two man /hi4d_pe_prompt_rewrite_20261020/README.md` §2（**净空契约：严格杜绝出现 `<image5>` 或目标图字眼**）
3. 训练侧真实输入分布：TikTok 训练时 VLM 只收 A 一张图；推理收 A + 骨架；Hi4D 推理收 4 图，**目标真值图永远不流入下游**。

被审对象（磁盘实测，非文档引用）：

| 资产 | 路径 | 行数 |
|---|---|---|
| TikTok 提示词银行 | `experiments/3.singel man/tiktok_pe_prompt_rewrite_20261014/prompts/{train,val,test}.jsonl` | 8574 / 1120 / 1156 = **10,850** |
| Hi4D 提示词银行 | `experiments/4.two man /hi4d_pe_prompt_rewrite_20261020/prompts/hi4d_{train,val,test}_prompts_v1.jsonl` | 5400 / 600 / 600 = **6,600** |

审查方式：只读脚本 `pass1..pass5`（已归档，见 §9），对 **17,450 条样本 × 2 种编译形式** 逐条判定，
每条判据都带样本 id 清单，可逐条复核。

## 2. 结论摘要

- **形式层面基本合格**：覆盖率 100%、零重复、零残留图号、长度分布健康。见 §3。
- **语义层面有三个成规模的缺陷**，且都直接打在任务目标的软肋上：
  1. **外观断言自相矛盾**（同一张源图/同一个人在不同样本里被描述成不同颜色的衣服）：TikTok **69% 的行**落在自相矛盾的组里，Hi4D **100%**。
  2. **提示词把"只有目标真值图才能提供的信息"写进了文本**：TikTok **90.3%** 断言表情/手指细节，**2.76%**（299 行）直接提"target photograph / target image / target frame / ground truth"；Hi4D **27.4%** 提"target photograph"、**16.2%** 提"fifth image"，其中分别有 214 / 112 行**整条找不到任何禁止措辞**（即正面引用）。⇒ 违反两套实验自己声明的契约。
  3. **Hi4D 的身份锚点在同一 episode 内自相矛盾**：30/30 个 episode 里"person 1"既被说成左边的人又被说成右边的人。这是**身份互换（identity swap）**的直接指令来源，而任务书对双人的核心要求正是不串味。
- **另外两条不是质量缺陷但会影响决策**：
  - 两个银行**目前没有任何训练/评测入口读取**（§7）。
  - 我在 pass1 写的两个指标是**假信号，已推翻**（§6），后续引用时别再拿它们当结论。

## 4. 不合格项（按严重度）

### 4.1 【严重】外观断言自相矛盾 —— 提示词在跟源图抢定义权

**判据**：同一个人（同一 `sequence_id`+`source_stem`；Hi4D 为同一 `pair`+`action`+`camera_id` 且按 person 分侧绑定）
在一批样本里被描述成穿不同颜色的同类衣物。衣着一帧内不变，故同组内一个 garment 出现 >1 个颜色 ⇒ **至少一方是编的**。

| 口径 | 结果 |
|---|---|
| TikTok，按 (sequence, source frame) 分组 | 1048 组中 **570 组矛盾（54.4%）**，涉及 **7487/10850 行（69.0%）** |
| Hi4D，按 (pair, action, camera) + 逐人绑定 | 30 组 **全部矛盾（100%）**，涉及 **6600/6600 行** |

逐字证据：

- `('00165','0053')` 24 条样本对同一张源图：`t-shirt ∈ {beige, brown, cream, green, white}`、`cap ∈ {brown, white}`、`sneakers ∈ {beige, black, tan, yellow}`。
- `('00056','0001')`：`top ∈ {blue, purple}`、`drawstring pants ∈ {blue, purple}`。
- Hi4D `('pair09','hug09',28)` 300 条：`P1/shirt ∈ {beige, black, blue, brown, cream, patterned, tan, white}`。

**为什么这打任务目标**：合同要求"**保持身份、服饰**一致"。逐样本提示词把外观细节写得很肯定，
但同一个源帧的细节在不同样本里互相冲突 —— 文本通道于是在**与源图争"衣服是什么颜色"的定义权**。
训练后果不是"没信息"，而是**梯度上教模型忽略文本、或把服饰描述成噪声**；评测时这类描述还会伪装成"细节保真度差"。

**口径边界（诚实）**：颜色词抽取靠正则，`gray/grey` 已合并；`denim/striped/patterned` 这类既是材质又是颜色的词
可能贡献少量软矛盾。所以这个数字应当读作"**外观断言不稳定的规模上限**"，
但 00165/0053 的 `t-shirt ∈ {beige, brown, cream, green, white}` 是硬冲突，不可能是口径问题。

### 4.2 【严重】把 GT 才可获得的信息写进提示词，并违反自己的净空契约

**判据 A（契约违规，Hi4D 自声明"严格杜绝 `<image5>`/目标图字眼"）**

| | TikTok | Hi4D |
|---|---|---|
| 提 "target photograph / the target image / target frame / ground truth" | **299 行（2.76%）** | **1811 行（27.44%）** |
| 提 "fifth image" | 0（三图协议，本不该出现） | **1070 行（16.21%）** |
| 其中"整行找不到任何禁止措辞"（正面引用，行口径） | 195 行 | 目标图 214 / fifth image 112 |
| 其中"存在一句非禁止式引用"（句口径，±90 字符窗口，是下限） | 178 行 | fifth image 188 行 |

两种口径都给，是因为它们量的不是同一件事：行口径统计"这行**从来没说过**别用那张图"，
句口径统计"这行里**存在一句**把它当信息源用"。句口径受 ±90 字符窗口限制，只能当下限读。

逐字证据（全部来自 `compiled_prompt_training`，即真正喂训练的那一版）：

- `train_pair01_fight01_cam52_000001_000020`：「…defined by the skeletons, **using the interaction read from the fifth image as ground truth** while the downstream editor sees only the …」
- `train_pair01_fight01_cam52_000001_000055`：「…**the fifth image's depicted fight01 engagement** only as a conceptual guide」← 连动作标签都漏进了文本
- `train_pair01_fight01_cam52_000008_000060`：「**using the fifth image only as an interaction reference** for torso contact, gaze d…」
- TikTok `train_0000097`：「…facial expression, and hand configuration **transferred from the unseen target photograph**」
- TikTok `train_0000430`：「the head direction and facial expression are **clarified from the actual target photograph rather than the skeleton**」
- TikTok `train_0000413`：「her legs adopt the visible stance **shown in the source image's target photograph**」← 自相矛盾的指代

**判据 B（推理时不可复现的内容，即便措辞合规）**：TikTok **9796/10850（90.3%）** 含表情/手指级断言
（`facial expression`、`lips closed`、`smile`、`eyes looking into the lens`、`fingers visible/spread`）。
骨架条件图不携带表情，离线重写时 PE 看过 B，**线上没有 B** —— 于是同一套提示词在训练分布与推理分布之间不可比。
`..._20261014/README.md` §7 已经把这条写成已知风险（"B 原图是作弊信息"），**但没有量化**；本次量化为 90.3%。
Hi4D 同类断言为 1217/6600（18.4%）。

**判据 C（与姿态无关的注意力占用）**：TikTok **6985/10850（64.4%）** 花篇幅指示保留
"TikTok logo text / username text / watermark"（例：`train_0000001` 要求原样保留 `@mikeilajduh` 字样）。
这是水印而非任务目标里的"场景一致性"，属于文本预算的浪费，也是模型最容易做不好的地方（文字渲染）。

### 4.3 【严重】Hi4D 身份锚点自相矛盾：person 1 一会儿是左边一会儿是右边

**判据**：同一 `(pair, action, camera)` 内，把 `person N` 与 `left|right` 绑定的句子取出来，看同一个 N 是否被指到两侧。

**结果**：30 个 episode 全部出现该矛盾 —— 每个 episode 里 `person 1` 和 `person 2` 都被同时说成 left 和 right（示例：
`('pair01','fight01',52) → {1:[left,right], 2:[left,right]}`；`('pair09','hug09',28)` 同）。

为什么要紧：`person 1 / person 2` 对应**固定的骨架文件**（`target_pose_A` / `target_pose_B`），
而"左边的人"是随帧变化的观者坐标。提示词用「The left man (person 1, …) must adopt the pose from person 1's isolated skeleton」
这种句式把**身份**钉在**侧位**上；一旦该帧 A 实际在右侧，这句话就是在**下命令换身份**。
合同对双人的要求是"拥抱/搂肩等接触交互"且不串味，`workflow-multiple` 那条线的实测结论也正是身份交换是主要失败模式。

**口径边界**：本判据证明的是"**断言之间互相矛盾**"，不是"某条一定错"——两人会在交互中换边。
要落到"每条样本对不对"必须拿 `target_pose_A_npy/B_npy` 的逐帧髋心 x 坐标当真值逐条比（本次未做，列为 §8 第一步）。

### 4.4 【中】角色词替换后的自指残句

训练形式把 `<image3>` 替换成长角色词，替换前没吃掉紧邻的同指引导语，产出"名词 + in + 同一个名词"的死句。

| 模式 | 命中 |
|---|---|
| TikTok `the joint skeleton in the target joint arrangement described in this instruction` | 48 行（0.44%） |
| TikTok `the joint skeleton of the target joint arrangement described in this instruction` | 44 行（0.41%） |
| TikTok `the target joint arrangement … described by/in the target joint arrangement described in this instruction` | 35 行（0.32%） |
| Hi4D `X in/of/by/from/to/for X`（三个角色词两两自撞，主要为 `the combined dual-person skeleton in the combined dual-person skeleton`） | **205 行（3.1%）**，其中同词自撞 198 |
| Hi4D `of the the` / `the the` / `and and` 这类叠词 | 32 行 |

规模小，但性质明确：这类句子**不再描述任何可执行动作**，`..._20261014/README.md` §3 描述的 `GUIDE_LEADIN`
清理规则没覆盖 `joint skeleton in`、`match the X in X` 这些搭配。另外 TikTok 有 **43 行**出现句首小写
（清洗剥词后没补大写），Hi4D 66 行。

### 4.5 【中】把骨架里"编出来的关节"写成确定事实

`TikTok_v3/dwpose_v1` 无条件渲染 18 个身体关键点，低置信度也照画（旧 §4.1 已确认）。
本次量化它对提示词文本的污染：`low_conf_drawn_body_pts` p50=2、p90=4；
**2591/10850（23.9%）** 的样本在 ≥4 个低置信关节的条件下仍然断言手指/手部细节。
银行里另有 573 行记录 `left/right_leg_chain_coherent=false`，同样会产出肯定的腿部描述。
（对照组：确实有样本写对了，如 `train_0000899`「…do not invent leg stance, knee, ankle or foot positions
from the skeleton's drawn leg lines」—— 说明契约头能表达这种护栏，只是没强制。）

## 6. 我自己测错、已被数据推翻的两个指标（别再引用）

1. **"inference 形式 8319/10850 重复、Hi4D 只有 1 种"** —— 假。归一时把文本截到 400 字符，
   而固定契约头尾本身逐字相同，于是头部撞在一起。全文归一后**两套银行零重复**。
2. **"TikTok 12.18% 提示词没有姿态意图"** —— 假。正则只认 `re-pose|transfer the pose|…`，
   而 PE 大量使用 `transfer only the body action`、`reconfigure the person's body into the pose`。
   逐条读前 6 条被判的样本，6/6 都写明了姿态编辑意图。收紧词表后 TikTok 为 0，Hi4D 为 33 条（0.5%）。
3. 另记一条口径教训：pass3 的 Hi4D 分组颜色矛盾（"100%"）**当时**混入了"同组两个人都映射到 `shirt`"造成的假冲突，
   pass5 改成逐人绑定后仍是 30/30 组矛盾，但例子换成 `P1/shirt` 这种带侧位的键才可信。

## 7. 链路事实：这两个银行目前没被任何训练/评测读取

在 `scripts/`、`src/`、两个实验目录里 grep `compiled_prompt_training` / 银行文件名，命中的只有
重写流水线自身（`pe_rewrite_tiktok.py`、`prompt_bank.py`、`apply_rescue_cleaner.py`、`chain_to_hi4d.sh`）。

- `scripts/train/train_iper_qwen21_body.py:252`：`Qwen21IPERCache(args.cache, prompt=args.prompt, …)` —— 仍是**单条写死提示词**。
- `scripts/train/train_hi4d_qwen21_dual.py:96-121`：`row_prompts()` → `build_dual_action_prompts(row["target_action"], …)`，
  自己按动作标签生成模板并 `write_prompt_manifest()` 落 `prompts_{train,val}.jsonl`（那是 `action_prompt_v2` 那一族，与 6600 条重写银行无关）。

⇒ 严格说，"**数据集里每一个样本的提示词**"当前有**两份**：模板版（正在用）和重写版（未接线）。
本审查审的是重写版 —— 只有它需要"逐样本质量"这个问题。
另外 TikTok 银行里有 **90 行 `rescue_cleaned=true`**，是正则从 PE 原始输出抢救出来的、没走正常编译器路径，属于需要单独复核的子群。

## 8. 整改建议（按性价比排序，全部可机械执行）

1. **先修 Hi4D 身份锚点（§4.3），它是唯一会造成身份互换的**。做法：用 `target_pose_A_npy/B_npy` 算该帧两人髋心 x，
   把「the left man (person 1…)」改写成**只依赖骨架文件身份**的措辞（"the person whose isolated skeleton is person 1"），
   删除观者左右；同时先跑一次"逐条断言 vs 逐帧几何"的核对，得到真实错误率再决定要不要重生成。
2. **给外观断言降权（§4.1）**：把服饰细节从逐样本文本里**摘出去**，改由每个 `sequence_id` / `(pair, action)` 一份
   的外观常量提供（源图不变，就不该逐样本重写）。银行里的断言既然互相矛盾，保留它们比删掉它们更糟。
3. **落实自己声明的净空契约（§4.2）**：`compiled_prompt` 里删掉一切 "fifth image / target photograph / ground truth" 指代
   （含禁止句式，因为"看不到的第五张图"本身不可接地）——Hi4D 1070+1811 行、TikTok 299 行；
   编译器加一条硬门：命中即拒，而不是靠 README 声明。表情/手指类断言（TikTok 90.3%）要么声明"由骨架推断"、
   要么下线，否则训练/推理分布不可比这条永远是定量的洞。
4. **补 `GUIDE_LEADIN` 搭配**（`joint skeleton in`、`match the X in X`、`the X defined by the X`）并把叠词/句首大写
   变成编译器断言：TikTok ≤127 行、Hi4D 205 行 + 32 行叠词 + 66 行句首小写。规模小、成本极低。
5. **对低置信关节样本加护栏**（§4.5）：`low_conf_drawn_body_pts ≥ 4` 的 2591 行，在 INSTRUCTION 里强制
   "只描述可见关节，不得推断被画出的低置信关节"——`train_0000899` 证明这个句式模型会用。
6. **接线前必须做的对照实验**：固定提示词 vs 逐样本提示词，按 `source_video_group` 做 cluster bootstrap
   （test 只有 3 个视频组，见 §4.6 旧结论），指标 body PCK / MPJPE / 身份。
   在 §4.1–4.3 修完之前跑这个对照没有意义——现在跑，测到的是"文本自相矛盾"与"身份互换"的合成。
7. **90 行 `rescue_cleaned` 单独复核**，不要与编译器产物混在同一银行里当同质数据。

### 11.1 怎么改的

入口：`scripts/data/clean_prompt_banks_v2.py`（跨实验复用，故进仓级 `scripts/`）。
