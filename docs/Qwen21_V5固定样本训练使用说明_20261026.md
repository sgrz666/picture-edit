# V5固定样本训练与同场景观察

这轮分别训练TikTok单人、Hi4D双人，每套累计300个成功optimizer update。每套只有1对进入训练，另1对同场景姿态只做观察；不能据此得出跨人物泛化结论。

| 数据 | Source | 训练目标 | 未训练观察目标 |
|---|---|---|---|
| TikTok 00031 | 0265 | 0374 | 0126 |
| Hi4D pair12/highfive12/cam4 | 000011 | 000082 | 000112 |

使用现有Plan A银行的`compiled_prompt_inference`原文，Q4不重新运行，文本不改。TikTok给Qwen两张图，Hi4D给四张图；Adapter外观始终只取第一张Source。原始画布分别为604×1080、940×1280，经`native_pad`补成608×1088、960×1280（宽×高）。模型仍为32层、4096↔512，Adapter不增加token。全程velocity-only，B=1、累积1、KV关闭，Qwen冻结。

数据、缓存、配置与输出位于：

- 单人：`/data/shangguanrz/pic-edit-experiments/qwen21_full_native_v1/tiktok-fixedpair-v5_20261025_v1/`
- 双人：`/data/shangguanrz/pic-edit-experiments/qwen21_hi4d_dual/hi4d-fixedpair-v5_20261025_v1/`

## 训练与继续

S0、S1、S2、S3预算依次为60、60、120、60。用户随后明确授权“不要停下直接训练300步就行”，外层编排器据此提交显式`advance-stage`，每个新阶段仍须通过真实梯度门禁。两套数据从同一个初始化文件开始，Hi4D不继承TikTok训练结果。

首次启动与已完成阶段的继续分别为：

```bash
$P scripts/train/run_qwen21_v5_fixedpair.py accept-and-train --kind both
$P scripts/train/run_qwen21_v5_fixedpair.py accept-and-train --kind both \
  --continue-tiktok-from /绝对路径/已提交阶段末checkpoint.pt
```

继续接口验证数据、模型、缓存、种子和初始化祖先，只接受60／120／240步的已完成阶段边界；保留AdamW moments。已在运行时不要重复启动。任意半阶段恢复使用现有训练CLI的严格`resume`，不把初始化或阶段修订冒充同阶段恢复。

2026-10-26继续时，TikTok已有240步已提交记录。进入S3曾把单人未启用的Interaction Head误列为必需预热项；现改为按实际训练路线要求预热，并在单人S3显式冻结Interaction相关组。该改动不改变网络参数名称、形状或既有权重。

Face候选为3000步编码器。旧Face72的轮廓顺序通过Embedding行和空间CNN前72输入通道的对应排列适配，参数basis不明部分明确重置；Hand和Source Detail标记fresh_unverified。完整账本在单人`initialization/migration_report_v2.json`。
