## 与当前 Face 链路的关系

当前 Full 主链：源 A 图像与源 A 的身份/外观特征，配合 B 的几何控制，通过 Face 模块和输出桥向 Qwen 注入残差。`execution.py` 的面部训练已有 flow、身份、感知和区域外约束；Target RGB 只用于离线监督或评测，不能进入实际生成条件。

BFS 则在 Qwen 主干的注意力和 MLP 层加入已训练的低秩更新，通过第二张参考图传递身份。它的张量键与我们的 FaceAdapter 检查点键不同；应把 LoRA 加载到 `pipe.transformer`，现有 Face 模块继续负责几何约束与第一阶段生成。

直接在一次采样中同时使用 Body/Face 和 BFS 尚有任务冲突：我们的源 A 输入带有 A 原姿态，BFS 的第一图约定偏向保持该图的姿态，Body 又要求转向 B。两阶段先生成符合 B 的中间图 C，再让 BFS 以 C 为第一图，可以明确输入角色。

BFS 第二阶段能追随的是中间图 C 中已经生成的表情。若第一阶段没有正确表现 B 的表情，BFS 没有额外的 B 表情信息可恢复。最终仍需分别验收头部角度、眼口表情和 A 的身份。

768 BFS 的六对中五对身份分数高于 Body 512；相对无 LoRA 768 的身份均值高约 0.0444，同时身体 PCK 均值降低约 0.0196。这个结果支持继续验证，也显示全图二次处理会带来姿态代价。

这些数字的限制：

- 只有六对，涉及的人物少；不能判断全数据集提升。
- Body 对照来自简化 Qwen Body，未与当前 Full Face 在相同样本、相同设置下比较。
- Body 512 与第二阶段 768 混有分辨率变化，不能全部归因于 BFS。
- 512 的无 LoRA 与 BFS 使用不同 prompt；768 探测 JSON 没有完整保存 sampler/prompt 等配置，因果对照仍需补齐。
- `source_target_ceiling` 的 0.6272 是两张真实同人帧的参考相似度，不是身份指标的理论上限。
- PCK 检查身体关节；它不能代替头部角度或表情一致性指标。

### 已定位的两个技术问题

初次加载日志出现 `img_mlp.gate_up` unexpected keys，说明该次加载遗漏了对应权重；后续脚本已增加拆分转换。现有 loader 只检查两类模块是否出现，正式接入应验证全部预期模块与张量、缩放值和权重覆盖率。

旧 `eval_iper_four_arm.py::PoseMetric.compare` 在计算距离时固定使用 512。原 768 探测的 PCK=0 因而不能直接解释为姿态失败。本轮在 CPU 上检测已有 768 图像，将检测坐标按实际图像宽高映射到比较器的 512 坐标系后得到上表结果；原 JSON 保留。

## 权重兼容核验

当前环境：diffusers `0.41.0.dev0`、PEFT `0.20.0`、Torch `2.8.0`、transformers `5.17.0`。底座为 `models/Qwen-Image-2.1`，32 层，hidden size 4096。

本轮 CPU 检查结果：

- V1.1：352 个原始张量键，rank 64。
- 现有转换后：384 个张量键，对应 192 个实际目标模块；全部能在当前 Qwen 2.1 模型中找到，形状匹配，张量有限。
- fused `gate_up` 的 A 矩阵共用到两个分支；B 的前 12288 行对应 `gate_layer`，后 12288 行对应 `proj`。
- 对 block 0 的低秩投影用固定随机输入检验，拆分前后最大绝对误差为 0。
- 反向拆分是错误映射，不能因为少量样本得分略高就选择它；官方 Diffusers 单文件转换也采用 gate 在前的顺序。[官方转换代码](https://raw.githubusercontent.com/huggingface/diffusers/main/src/diffusers/loaders/single_file_utils.py)

这验证了映射结构及所测投影的数值一致性，不能替代新的完整采样验收。当前 pipeline 每次调用重新创建条件 KV cache，本轮没有发现跨调用复用旧 KV 的证据。后续若保存自己的多图/prompt 缓存，应把输入顺序、prompt 和 LoRA 版本纳入对应记录。

## 三种接法

| 方案 | 改动与收益 | 代价或尚需解决的问题 |
|---|---|---|
| 两阶段局部头部修复（推荐） | 保留现有 Body/Face 输出；BFS 独立可关闭，方便验证身份增益 | 多一次采样；需头部 ROI、贴回和表情验收 |
| 单次采样叠加 LoRA 与现有控制 | 有机会节省第二次采样，结合原生参考图与几何控制 | 第一图姿态角色冲突；需重验多图条件、控制强度与区域外变化 |
| BFS 作为教师，再训练 Face 学生 | 筛选 BFS 的高质量面部结果作为附加监督，长期降低推理成本 | 教师也有错误；需质量筛选、独立人物划分，不能直接拿所有输出当真值 |

## 推荐方案的具体输入与边界

```text
源人物 A + 目标 B 的几何/表情控制
                 ↓
       当前 Body/Face 生成中间图 C
                 ↓
第一图：C 的头部/颈部局部区域
第二图：A 的清晰头部参考，包含五官与必要发际线
                 ↓
      Qwen 2.1 + BFS head LoRA
                 ↓
  局部结果缩回原尺寸，以软蒙版贴回 C
```

第二阶段先验证 768/1024 的局部编辑。高分辨率推理不能补回参考 A 中本来没有的细节，参考图需可见且质量合格。区域应保留目标头部姿态、颈部与光照上下文，不仅截取五官。

按 B 的几何或中间图检测定位头部，按源 A 的身份对应关系选择参考。不能在双人图里无条件使用“最大脸”。首轮限定单人场景，双人扩展另验身份与 ROI 的对应。

第一阶段关闭 BFS；第二阶段按独立 adapter 名称启用，结束后禁用或卸载，防止影响下一次 Body 生成。现有检查点不融合、不覆盖。无有效源脸或无法可靠定位头部时，保留 C 并记录回退。

贴回蒙版覆盖头部与必要的颈部过渡，限制在确定的 ROI 内。蒙版外直接保留 C 的像素；身体、衣服和背景变化单独检查。B 的真实 RGB 不作为这一方案的生成输入。

## 首轮验证与通过条件建议

固定 30 对验证样本，覆盖多个身份、头部角度、强表情、眼镜、光照与脸部尺寸。使用固定 seed、步数、输入预处理、prompt 和输出分辨率，分开比较：

1. 当前 Full 的 Body 与 Body+Face 输出。
2. 同样局部第二阶段但关闭 LoRA。
3. 同样局部第二阶段启用 V1.1。
4. 同样局部第二阶段启用 alternative。

LoRA 强度先在验证集试 0.6/0.8/1.0；同一比较中只改变待测变量。alternative 已包含作者的 MLP 权重调整，不再重复应用同样的缩放。

建议验收同时满足：对 A 的身份分数改善、有效脸覆盖率不降低、B 的头部角度与表情不明显退化、身体 PCK 不下降超过 0.01。蒙版外像素应与 C 一致，拼接边缘人工检查。0.01 是本项目拟采用的验证门槛，不是仓库给出的性能保证。

样本选择与强度调整只用验证集，最终测试身份独立保留。记录逐样本结果和失败原因，不能只汇报成功案例的均值。
