## 三、分方法要点

### 3.1 PAI Qwen-Image-2.1-Fun-Controlnet-Union（同基座，最重要的可运行对照）
- **架构**：经典 ControlNet 并行控制流——16 个控制块副本（与基座单流块同构）注入 32 层中的偶数层 `control_layers=[0,2,...,30]`，每个注入点经零初始化 `before_proj`/`after_proj`（无 zero-conv，零 Linear）；控制流与基座无 cross-attention；`control_in_dim=129` = 控制 latent 64 + mask 1 + masked-image 64；推理统一标量 `control_context_scale`。
- **训练配方**（VideoX-Fun `scripts/qwenimage21_fun/`）：batch 1、1024 分辨率、LR 2e-5 + warmup 100、max_grad_norm 0.05、weight_decay 3e-2、只训 `control.*`；**10% 控制 latent 丢弃**（保留无条件路径）；条件混训、**无 control_mode embedding**；两阶段 CFG 蒸馏（teacher scale 3.5 → 推理 cfg=1.0 单前向）；总步数未公布（checkpoint-10000 暗示万步量级）；条件配比未公布。
- **DWPose 渲染规范**：仓库自带 `comfyui/annotator/dwpose_utils/util.py`——18 色固定调色板画 17 条肢体椭圆条（颜色×0.6、stickwidth 4、关节半径 4）、手 20 边 HSV、脸白点；黑底、分辨率 16 倍数、与目标同宽高比。
- **许可证**：Qwen Research License——**仅限研究/评估，任何规模商用都需单独授权**；衍生模型须标注 "Built with Qwen"。
- **对我们的适配**：姿态跟随基线可跑（不保身份）；训练配方多处可直接抄进完整版适配器（10% 信号 dropout、条件混训、CFG 蒸馏、输出端零门 + 全局 scale 旋钮）；「注入点在块输出端」与我们「hidden state 加残差」同族，可作注入位置的消融对照。

### 3.2 Qwen-Image-Edit-2511 官方原生基线（本地已有权重）
- 2509 卡原文：*"changing a person's pose while maintaining excellent identity consistency"*、*"multi-image input also supports commonly used ControlNet keypoint maps — for example, changing a person's pose"*。2511 进一步改进一致性与多人合成。
- diffusers 无专门 keypoint 传参——keypoint 图作为 `image=[...]` 列表元素传入，无官方示例代码（需自行试 prompt + 图序）。
- 20B bf16 ≈ 55-60GB 显存，84GB 单卡可完整跑。
- **这是"保身份换姿"任务的官方对照，正式报告必须有它**。

### 3.3 AnyPose（社区事实基准）
- 双 LoRA（base 6250 步 + helper 6000 步，各 295MB、强度 0.7）+ 官方配 Lightning 4 步加速；核心提示词（原文含拼写错误 facical）：
  > Make the person in image 1 do the exact same pose of the person in image 2. … The position of the arms and head and legs should be the same as the pose we are trying to copy. … Don't change the identity of the person in image 1, keep their appearance the same…
- **训练数据：Blender 摆姿 3D 角色渲染**（覆盖倒立、桥式等极端姿势）——意味着我们用 SMPL-X mesh 渲染的"假人"参考图理论上正好落在其训练分布内。
- 已知失败模式：多人必挂、2D/扁平风格差、超复杂姿势差、参考图背景可能串入。
- 加载风险低于 BFS（官方 Space 用 diffusers `load_lora_weights`，约 100 个 Spaces 在用），但接入时仍应做加载后键名核对。
- 作者已在 2.1 生态动手（QI_2.1_AnyAngle 相机角度 LoRA），2.1 版 AnyPose 在其路线图上可关注（讨论 #13 有人求 2.1 版未回）。

### 3.4 BFS-Best-Face-Swap（本会话已完成实测，结论引用）
- @512 两阶段无收益（0.328 vs Body 0.417），@768 有真实但有限收益（0.492，5/6 对胜出，LoRA 净贡献 +0.044），仍低于自家 Body+Face+A脸图 @512 的 0.546（测试集口径）；body swap 方向相反且格式敏感不可用；ComfyUI→diffusers 键名需手工转换（融合 `gate_up` 24576 → `gate_layer`+`proj` 各 12288）。

## 四、行动建议（优先级排序）

1. **【P0·约1天】Edit-2511 官方基线跑通 iPER 50 对**：本地权重已齐；`QwenImageEditPlusPipeline`，image=[A图, DWPose骨架图]，指令用 2509 卡的 pose 编辑措辞；测身份余弦 + PCK + 背景/人体 MAE（与项目协议同口径）。这是对外报告里说服力最强的官方对照。
2. **【P0·约半天】AnyPose 基线**：下 2×295MB LoRA（+Lightning 可选），image2 用 SMPL-X mesh 渲染人形（恰好匹配其 Blender 3D 训练分布）；同协议评测。注意基座是 2511，对比表要标明基座差异。
3. **【P1·约1天】PAI 2.1 Union 姿态跟随基线**：下 7.55GB 控制权重 + clone VideoX-Fun，DWPose 图按其 18 色规范从现有资产渲染；只比 PCK（它不保身份）。它同时是"2.1 上最接近我们架构的公开实现"，注入位置/参数量可进消融表。
4. **【P1】把 PAI 训练配方移植进完整版适配器后续训练**：10% 信号 dropout、条件混训无 mode embedding、两阶段 CFG 蒸馏（推理省一半前向）、输出端零门 + 全局 scale。
5. **【P2】新颖性叙事**：2.1 基座上"姿态专用控制 + 身份保持 + SMPL-X 多几何条件"生态位完全空白——正式报告的 positioning 直接引用本调研的搜索盲区说明。
6. **【持续】踩坑清单维护**：ComfyUI→diffusers 键名转换函数（已在 `~/project/pic-edit/bfs_explore.py:convert_bfs_state_dict`）、PAI yaml/config 不匹配会静默丢键的警告、AnyPose 接入前做键名核对。
