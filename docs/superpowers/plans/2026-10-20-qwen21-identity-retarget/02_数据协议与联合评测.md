# 数据协议与姿态–身份联合评测方案

**目标**：让不同模型、不同几何模式和不同分辨率的比较有相同解释口径，避免把控制图/GT错误、检测失败或数据泄漏当成模型能力。

**责任边界**：本文件定义数据角色、划分与评分。03引用本文件，不自行改变分母；05定义如何生产几何，不决定网络是否胜出。

## 1. 一条样本至少包含四个角色

| 角色 | 内容 | 是否允许进入生成条件 |
|---|---|---|
| Source A | 身份、源RGB、脸/人物裁图、源shape、源scene/camera | 允许；所有外观bank只来自A |
| Driver B | 局部关节旋转、头向、表情、动作/接触关系 | 允许经过几何提取/重定向后进入；RGB默认不进入Adapter任务条件 |
| Requested target C* | A形状承载B动作，经过布局/接触求解的最终目标几何 | 允许；所有dense maps、ROI、pose guide从同一状态重渲染 |
| Supervision Y | 与实际任务严格或经审核配对的目标图像、离线监督标签 | 只进入训练损失/离线评测，不能进入source bank或条件缓存 |

Source和Driver可能是同一人不同帧，也可能是不同人。名称B并不自动意味着B图像可作为GT；必须看下面的supervision_kind。

## 2. 数据类型与可用损失

以下为**拟新增的数据协议字段**，不是当前CLI选项：

| `supervision_kind` | 几何与图像关系 | 可用 | 禁止 |
|---|---|---|---|
| `paired_driver_exact` | 现有GT，driver参数/mesh/camera未改变 | 全局/区域flow；同身份脸与目标姿态监督 | 任意换beta/根位移后还沿用该标签 |
| `paired_identity_refit` | 同一身份多帧统一shape后，对目标帧重新拟合并独立验收 | 置信度加权paired训练，明确有拟合误差 | 叫作exact；降低旧exact guard来偷渡 |
| `unpaired_source_shape` | A身份/shape与跨身份B动作组合，没有真实目标RGB | 完整生成后的源ID、目标几何、背景与人工评价 | `flow_target = noise - latent(B_rgb)` |
| `synthetic_paired` | 可控人体/纹理渲染或其他明确合成配对 | 独立合成域训练/诊断 | 冒充真实人像GT，混入真实测试均值 |
| `pseudo_paired` | 教师产生的目标图，有筛选和教师来源 | 可选后期蒸馏，单独研究 | 当真实GT；把教师失败当学习目标 |

主线先用 `paired_driver_exact` 完成网络机制实验，用 `unpaired_source_shape` 验证真实任务。`paired_identity_refit` 是后续增强路线，必须单列版本和审核；初始实现不需要它才能开工。

## 3. 数据规模与划分

以下规模是计划配额，**不是声明磁盘上已经有足量合格样本**。P0先登记真实可用数量；不足则如实缩减并修改预登记，不复制同一身份帧伪装独立样本。

| 名称 | 来源与规模 | 用途 | 限制 |
|---|---|---|---|
| `train_debug12` | train中iPER/TikTok/Hi4D各4对，共12对、按预期16个人物槽位 | 工程、过拟合、梯度、恢复测试 | 不用于最终效果宣称 |
| `train_pilot192` | train中各64对，共192对 | E05相同预算训练 | 按身份/原视频均衡，保存实际抽样次数 |
| `dev12` | val中的固定12对，每数据集4对 | 便宜的机制筛选 | 只调参，不能称holdout |
| `val24` | val中各8对，共24对，包含dev12 | 配对筛选与子集失败分析 | 与dev12嵌套，不作为独立确认集 |
| `retarget24` | 仅使用val身份/视频组合的8 iPER、8 TikTok、8 Hi4D任务 | 跨体型/跨身份研究 | 无真实跨身份GT；同一个A/B被多次组合要按身份聚类 |
| `val96` | 既有val锁可容纳时使用96对 | 冻结候选前扩大验证 | val24是其中子集，不重复计算独立样本量 |
| `holdout` | 复用既有test锁，数量以审计后为准 | 最终一次性评价 | 不用来选scale、checkpoint、几何拟合策略 |

如果沿用仓内既有1536训练、96验证、1024测试的锁，先核对实际文件、身份重叠和预处理可用性，不能只凭数字建立目录。新小集合由原划分派生，不重新把test身份分给train。

还要审计历史使用：已反复用于选提示词、校准torso比例或挑checkpoint的旧test样本，只能叫“历史回归集”。文件名写test不代表它仍是未见holdout。若整个旧test已用于开发，应从尚未用于选择的独立身份/视频建立新锁；没有这种数据时诚实交付回归/验证结论，不宣称盲测泛化。

`train_debug12` 的建议身份覆盖门槛：可见、足够清晰的人物槽位中，有效FaceID至少75%，且单人/双人各有有效样本；两人都有效的双人例至少2对。不可见脸作为单独挑战集保留，不为了凑覆盖强行接受错误检测。该门槛只控制身份学习探针，不代表自然数据的人脸检出率目标。

## 4. 分组和难度标签

划分单位优先是演员/身份，其次是原视频/Hi4D pair，而不是帧。iPER不同衣服序列可能属于同一演员；同一Hi4D人物跨pair的情况也需核验。无法确认身份关系的样本标记 `identity_group_uncertain`，不得作干净身份外推结论。

每条记录最少登记：

- `source_identity_group`、`driver_identity_group`、`sequence_id`、人物映射、split和来源SHA。
- 人数、源/目标可见脸数、源脸像素短边、目标脸ROI面积、yaw/pitch难度或可用替代标签。
- 全身/半身、手与脸遮挡、动作差距、接触类型、相机是否已标定。
- shape差异：相同body backend下的rest身高比、肩/髋宽比、肢段比；不要直接比较不同SMPL模型的beta欧氏距离。
- source shape置信度、driver关节有效性、是否使用常数躯干回退、是否用了接触求解fallback。

body尺度、camera估计不可靠的样本应保留为挑战子集，但不进入“体型解耦精确性已证明”的统计。

## 5. 缓存与记录协议

将以下清单分别保存，禁止一个JSON既充当条件又充当监督：

```text
data/selection_lock.json            # split、样本ID、抽样规则、角色映射与SHA
data/conditions.jsonl               # A外观来源 + B动作/最终几何，不能含Y外观特征
data/supervision.jsonl              # Y路径、supervision_kind、配对审核
data/identity_coverage.json         # 有效/无效原因、source detector版本、面部大小
data/geometry_audit.jsonl           # driver/requested/solved、camera/layout、feasibility
configs/evaluation_protocol.json   # 版本、检测器、阈值、分母、seed和采样配置
```

这些是未来实验目录的产物，本轮不创建空数据或假锁。

缓存键包含source图/裁图、人物顺序、raw特征模型、camera、shape/pose状态、renderer版本、depth codec、最终几何、prompt、reference顺序、画布/ROI变换。修改其中任一项必须失效对应条件缓存。冻结VAE/VLM/ArcFace/DINO原始特征可缓存；可训练resampler或projection输出不能跨optimizer step detach复用。

记录实际token网格和输入图数量。每个新run的 `request.json` 若存在，绝对路径要逐项复核，不能复制后继续读写旧run。

## 6. 统一生成协议

默认诊断：512×512、40步、seeds 42/43、BF16冻结网络、CFG1、无KV cache，沿用固定Qwen scheduler/dynamic shift。任何偏离都写进arm，不悄悄改成更有利的设定。

源照片、目标几何和目标画幅尽量相同，但不同方法接收条件的接口不同：native可将骨架作为reference，Union作为control，Full作为typed条件。这叫“同任务系统比较”，不叫完全同输入的架构因果实验。

同一机制实验必须保持checkpoint、source图、prompt内容、reference顺序、geometry signature、noise seed、采样设置固定。角色数变化时使用预登记的语义等价模板，例如去掉骨架reference后不能继续写“动作来自image2”；脸裁图增加后不能让它被误指为姿态图。提示词字节变化作为输入干预的一部分记录。

source脸裁图与更高输出分辨率分开测。不同分辨率的seed只能保证各自可复现，不能声称它们拥有相同维度的初始噪声。

## 7. 姿态、体型、身份和背景分开评分

### 7.1 姿态与几何

- 固定body关节集合与target-visible denominator。首选共同COCO17映射的PCK@0.02/0.05（按画布对角线归一），漏检的目标可见关节记失败；关节置信度阈值在P0锁定。
- 躯干归一PCK作为另一列，不能同对角线PCK混排。报告head yaw/pitch/roll或可信替代指标、表达和手部细节；body PCK高不代表头向/表达正确。
- source_shape结果对照最终 `solved` 或明确fallback状态的C*投影，不能仍用原B像素点作为全部GT。
- 另报相对于B的动作差：局部关节旋转/肢段角、接触拓扑，分离“动作保留”和“屏幕位置”。有可靠3D标签时用3D；图像拟合得到的3D只作代理。
- 人数错误、额外肢体、骨架线、遮挡失败必须独立人工标记；不让检测器对画出的骨架给分后自动通过。

### 7.2 人物ID与外观

- FaceID采用对源A的ArcFace cosine；固定识别模型、对齐和检测规则，尽可能另用未参与训练的评价器/人工配对盲评确认。
- 同时报告共同有效集合均值、每臂检测覆盖、全样本失败率；无脸分数为null，不能把null当0混成cosine，也不能丢掉失败后只报高均值。
- 双人先按几何/预登记映射匹配，再计算各自ID及交叉ID矩阵；不得按最高ID分事后配对以掩盖身份互换。遮挡导致映射歧义时标注，不强行猜人。
- DINO/人物crop相似度只说明身体与服饰外观，不替代FaceID；服装图案、发型和配饰辅以固定crop与人工检查。
- source-target同身份不同视角相似度是难度参考，不是数学上限。大侧脸、闭眼和表情变化可能影响识别器，必须分层报告。

### 7.3 体型解耦

工程级：requested/solved中的betas必须与指定source一致；在指定backend的rest状态核对身高、肢段、肩髋宽；求解不能靠改betas满足接触。

图像级：优先以合成可控条件或可靠多视角标注验证；真实单目成图中的身高/宽度不能直接从bbox推断为物理体型。可用同姿态对齐后的轮廓/肢段比例、独立SMPL(-X)拟合以及人工“是否像A的体型”评分，但明确这些是代理，不能用生成器自己的输入beta作为输出体型已保持的证明。

### 7.4 接触与背景

几何级接触残差以米报告，只能在尺度可信时解释厘米阈值；同时报告穿透/地面支撑检查、solver fallback率。满足少量vertex接触不代表全身无碰撞。

生成级接触报告端点/人体检测可用性和盲评合理率。背景使用A与C*人体mask并集以外区域，区分新暴露区域；精修另报ROI外像素差和边界伪影，不能只测裁图本身。

## 8. 统计与选型

所有臂按sample_id/seed配对；先在样本内汇总seed，再按独立身份/视频聚类。双人或跨人组合重复使用身份时用预登记的group规则或多维聚类，不能将重用身份视为独立。

报告各子集、最差一组和失败覆盖；不只报全局均值。dev12与val24用于筛选，不产生强总体显著性结论。val96扩大验证、至少第二个训练seed用于检验训练随机性；最终holdout只在所有选择冻结后运行。

推荐结果表列：方法、checkpoint、geometry模式、样本/独立身份数、姿态、ID与覆盖、体型代理、头向/表达、接触/人数、伪影率、背景、秒/图、峰值显存。03中的运行预算是最终输出数量，实际VAE/ROI调用与训练耗时另列。

## 9. 数据门禁清单

- [ ] 所有A/B/C*/Y来源和人物映射可追溯，source bank没有target RGB/target ID。
- [ ] train/dev/val/test身份/视频关系已审计，未知关系有标记。
- [ ] 有效FaceID覆盖达到探针要求，且双人两侧均有可学习例。
- [ ] 几何三态、camera/layout与GT类别匹配，所有修改能使缓存失效。
- [ ] 指标分母/失败处理固定，人工伪影检查有盲评顺序和完整记录。
- [ ] 当前成图与历史报告的PCK/ID定义分开，未把DINO当ArcFace。
