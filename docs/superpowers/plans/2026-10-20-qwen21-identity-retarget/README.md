## 当前依据

上游：[Full / Pro / Union 研究报告](../../../../research/qwen21_adapter_selection_20261020/REPORT.zh-CN.md)。已有证据支持“身份条件和监督覆盖需要优先改进”，没有证明某个新结构已经最佳。旧512四臂共同30脸中，Body、加源脸裁图/角色提示、再加Face的ID为0.3953、0.4719、0.4802；Pro 200步8个人物仅2人有有效FaceID。数字是历史证据，不是本计划目标完成情况。

研究主线为：**数据与几何审计 → 当前能力基线 → 身份输入和注入机制消融 → 有效ID监督 → 重定向与Adapter交叉验证 → 高分辨率/局部修复 → 冻结设置后最终测试**。

不以参数越小为目标；不直接扩训原样Full；也不预先宣布完整Union一定胜出。优先复用现有Pro工程和Union原生控制骨架，同时保留Full及原生Qwen对照。

## 重要的代码现状

- `src/pose_control/qwen21_pro/geometry.py` 已有 `retarget_request`：替换为源betas，其余动作、根朝向、位移、相机沿用driver；这不是完整的“A场景编辑”布局策略。
- `geometry_preparation.prepare_geometry` 已区分 `driver_exact` 与 `source_shape`。后者没有原图精确GT，禁止直接拿原B图训练，这个约束继续保留。
- 接触求解已限制根平移不超过源rest身高5%、body关节修改不超过5°；没有承诺全身无碰撞。
- 共享Union包已有 `build_transformer(scope="joint"/"target")` 和 `scoped_transformer_class`；target模式屏蔽hint的prefix位置。优先复用做对照，不重复造实现；当前Pro CLI未直接暴露scope开关，需在后续实验入口明确接线。
- 本地与远端有漂移：两份Pro几何文件本次SHA一致，但 `src/pose_edit/geometry.py` 不一致。远端 `source_torso` 优先使用实测A躯干，本地还只有常数回退版本。实现前先对账，不能覆盖远端已有修正。
- 本地缺完整的共享 `qwen21_union` 包和Pro测试镜像；远端冻结代码根有19个Pro测试文件。不要以本地几份源码可读，就认为完整训练环境已经就绪。

## 怎么使用与核验

本轮只写计划。第一轮实施按06的批次A开始：核对工作区和输入、建立数据锁、做几何审计，再跑少量基线。所有新增接口、字段、测试与实验脚本在正文中均标为“拟新增”，不是今天已经可执行的功能。

现有研究证据可在仓根只读复核：

```powershell
python -X utf8 research/qwen21_adapter_selection_20261020/scripts/audit_evidence.py --verify
```

实验必须使用新run名，不覆盖旧产物；模型、缓存和图片放服务器 `/data/shangguanrz/`。这份目录只保存计划，不保存训练结果。当前结论和执行完成情况以后分开记录：更新执行日志时，不把尚未完成的计划勾成已完成。
