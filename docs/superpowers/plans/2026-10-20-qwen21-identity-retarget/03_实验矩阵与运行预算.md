# 分阶段实验卡与运行预算

**目标**：把架构、输入、监督、重定向和分辨率的贡献拆开。以下均为拟执行实验，既有历史输出只能作为标记清楚的参考，不能填充未执行的单元格。

**统一设置**：数据定义见[02](02_数据协议与联合评测.md)；默认512、40步、seeds42/43、CFG1、固定scheduler、禁用KV cache。预算是最终结果图数量上限，不包含几何可视化、训练中间量或额外ROI调用。不能把整张表一次性全部排队。

## 2. E00：首先把“实验能否解释”做成门禁

- **处理**：核对两侧源码/依赖；登记现有Full、Union、Pro checkpoint和实际训练步数；统计数据/脸ID/接触覆盖；核对GT类别；读取当前Pro验证run的实际完成状态。
- **固定**：不修改权重、不重写输入、不打开训练、不重新划分test。
- **产物**：`baseline_inventory.json`、`selection_lock.json`、`identity_coverage.json`、`cache_audit.json`、`status_snapshot.json`。
- **通过**：条件与监督隔离、当前导入文件可追溯、没有已知跨split身份泄漏、有效身份探针可形成。
- **失败处理**：先补缺失信息/合格训练例；不要以旧六例有loss下降绕过身份覆盖不足。

## 3. G00：不加载扩散模型的几何研究

每例输出A源shape rest视图、B driver、A-shape requested、contact-solved，以及相机/画布投影、normal/depth/owner/ROI。记录shape不变、局部pose差、root差、contact残差与fallback。

先用同body backend的可控fixture测试尺度/坐标，再看真实估计。覆盖两人遮挡、身体高矮差、半身裁切、背面和伸手前探。像素投影数值对账容差只证明实现一致，不代表SMPL估计与真人完全吻合。

现有R2可以先跑几何；R3布局和R4接触组合的新增部分按05实现后再纳入。`driver_exact`与真实B GT配对，任何改形/求解后的版本不得继承这条资格。

## 4. E01：五臂当前能力快照

| 臂 | 输入与checkpoint | 用途 |
|---|---|---|
| N0 | 原生Qwen＋A＋动作文字 | 原生身份/编辑能力参照 |
| N1 | 原生Qwen＋A＋骨架reference | 原生显式姿态输入参照 |
| F0 | 当前Full Body/Face checkpoint及其真实兼容输入 | 已有完整任务Adapter能力 |
| U0 | 原始Union发布权重＋本仓reference pipeline，scale1 | 官方控制先验 |
| P0 | 现有Pro200 checkpoint，原训练scope，scale1 | 当前任务增量 |

source与目标几何尽量同源，但不假装各接口输入完全相同。先执行dev12的120张，人工检查后再补剩余12对；val24总上限240张。旧Pro以legacy训练、current几何推理的差异写入配置；条件kind不兼容时保留独立层，不静默重建缓存。

**结论边界**：这是当前系统对比，Full训练更久、Union有大规模预训练、Pro只有200步，不足以证明架构优劣。N0如果不动姿态，其高ID不能算任务成功。

## 5. E02：源脸信息有没有真正用上

Union与当前Pro各做 `A原图` / `A原图＋合格源脸crop及角色提示`，其余几何、scale、seed固定。双人分别给各自crop，slot映射不可换。源脸无效时记不可用，不能用最大脸补齐另一人的身份。

比较同集合ID、pose、头向、表达、reference读取反应。增加crop后，缓存必须包括新图SHA、顺序和prompt；Pro raw bank若保持不变，本实验测的是原生reference增强，不把它叫face-bank改造效果。

**反证**：如果换source脸crop不改变目标脸而更换pose明显改变图，说明该输入在当前条件下可能被忽略；先排查角色、source图质量及控制强度。不要直接因此加宽网络。

## 6. E03：骨架泄漏与输入分布

固定Union发布权重，做2×2×3因子：

- control guide风格：当前workflow风格 / 按官方示例预处理规范重建的guide；同一关节坐标、相同有效性，避免把“风格”与“姿态”一起改。
- reference路由：`source-only` / `source＋同一guide`；control路径始终有guide。
- scale：0、0.5、1.0。

相同reference、scale0时更换仅control图理论上不影响输出，作为接入检查并允许去重；reference包含guide时，风格也会改变reference，不能误做scale0完全等价断言。提示词角色数随路由按预登记模板调整。

**必须人工标记**：guide线泄漏、色块、额外肢体、源脸变化。高PCK但有骨架泄漏单列失败，不用它选“最强姿态档”。旧hard_02去掉guide reference仍泄漏，是已知反例，本轮要检验其覆盖面。

若官方风格也持续泄漏，检查相同source的depth控制对照（追加单独登记，不混入本288张），再判断是否需要训练适配。style修改通过重渲染完成，不手工修原产物。

## 7. E04：先复用现有scope，而不是写新网络

`qwen21_union.pipeline.build_transformer` 已支持 `scope="joint"` 和 `scope="target"`；target通过原生target mask屏蔽hint的prefix位置。固定Union原权重，在已选输入上比较两个scope×scale0/0.5/1。

记录：每层prefix激活相对native的差值、target hint RMS、脸ROI局部RMS、输出差与联合效果。target模式下prefix路径的预期不变应在相同输入、同precision/后端、无额外prefix增量的条件下检查；full trajectory的目标图可以变化。

**边界**：当前Pro CLI未暴露scope，已有Pro200 checkpoint metadata锁定joint。E04只用未训练的Union原权重，不偷偷把旧Pro checkpoint改scope。E05从头构建选定scope的候选并记录到新checkpoint。

## 8. E05：身份路径与直接监督的2×2实验

这里比较的是同一V2身份模块的注入位置，不把旧V1与新V2的所有改动揉成一个因果判断。当前Pro200继续作为E01背景对照。

共同改造：保留geometry/body-appearance任务流；关闭旧fusion内FaceID贡献；新增同样的FaceBank/IDBranch。C/B两组使用相同特征、宽度、head数、stage对应关系与参数预算，分别写control state或base target ROI。它们都属于“身份已拆开”的V2，V1→V2总收益另报。

| 臂 | 身份写入位置 | loss |
|---|---|---|
| C-F | 原生control block之后、after_proj之前 | global＋region flow |
| C-I | 同C-F | 同flow＋直接可微ID |
| B-F | 对应base block完成geometry hint后，target face ROI | 同flow |
| B-I | 同B-F | 同flow＋同一直接可微ID |

先只加ID loss，不同时加DINO/LPIPS/表达新loss。已有flow和独立评测负责监测姿态/表达回退。若后续加保持项，登记新实验；否则无法解释2×2。

### E05a：12例、200更新，只验证能否学会

所有臂从同一官方Union与可比任务初始化开始，**不继承Pro200学到的任务权重**。相同样本序、噪声/时间采样、batch1、累积1、lr初值1e-4、warmup32、clip1；使用现有FP32任务参数与BF16冻结网络。不把这些初值称为最优值。

对两条含ID臂，初始开发权重 `lambda_id=0.1`，每4个optimizer update请求一次。该update四臂统一从同一native schedule的sigma≤0.35区间抽取时间步，其余update沿用共同的全范围抽样；C-F/B-F使用相同低噪声样本但不计算ID项，避免把噪声分布变化混入loss因素。这个分层采样协议属于新实验配置，必须记录，不说它是原训练默认。记录实际使用频率/有效脸数。前32更新后若几乎无有效ID梯度，判为监督覆盖/接线失败，先修复，不继续“跑满200再说”。loss权重过大导致稳定性问题时，修改两条ID臂相同设置并重新登记，不只救一个臂。

在step0和200完整采样；4臂×2时刻×12对×2seed最多192结果。零初始化使部分step0可完全等价时，验证后复用。旧fixed18函数硬编码6例，不直接调用它评12例；拟新增通用固定评测器采用每例3个噪声位置，即36位置，旧gate保留不改。

### E05b：192例、1000更新，开始看泛化

通过工程/可学习门禁的臂从共同可比初始化重新训练，不用挑选不同overfit checkpoint起跑。默认先1000更新，500/1000两次在val24完整采样，最多384结果。若某臂稳定数值失败，保留失败标记，不算为0幅“完成”。

至少对最终前两臂增加第二个训练seed；新增预算单独登记。比较训练步数、实际sample draws、GPU时长和可训练参数，不能仅按“都是1000步”称算力完全相同。

**解释**：C-I优于C-F、B-I优于B-F说明ID监督有价值；B-F/B-I优于同loss的C组才支持base路径；交互项说明位置和监督协同。某一臂赢一例不构成总体结论。

四臂都已拆分ID，因此不能单独证明“拆分优于旧V1共享fusion”。如需作此结论，追加相同数据/采样/有效监督的V1-F与V1-I两臂：过拟合额外最多96结果，小训练额外最多192结果，训练预算另列。旧Pro200的历史结果不能代替这两条匹配重训。若只需选择C/B注入位置，则不强制追加。

## 9. E06：把空间、层深与时间分开调

固定E05的独立base ID候选与checkpoint，只调整其尚未混入ID的control hint在face ROI的gate，base ID强度保持相同。该hint还可能含body appearance影响，所以本实验称“控制hint衰减”，不声称已经得到纯几何语义方向。若只有C路线有效，暂缓本实验：C的ID已经传播进control chain，直接缩放最终hint会同时缩放ID，不能当成独立geometry gate；需要另登记输入侧干预或显式双路分解，重新说明成本与变量。

| 设置 | 规则 |
|---|---|
| S0 | 原始强度 |
| S1 | sigma≤0.35时face区域control hint乘0.25，其余不变 |
| S2 | base层index≥16时face区域control hint乘0.25，其余不变 |
| S3 | 同时满足任一条件即乘0.25；交集不重复乘到0.0625 |

最多96结果。阈值只是预登记诊断起点，不是“后半层负责纹理”的已知真理。测头向/表情、脸位置与ID，防止通过不执行头动作提高ID。若有效，下一轮才讨论可学习gate；冻结推理gate与重训gate结果分开。

## 10. E07：重定向与Adapter的真正连接实验

### E07a：shape×生成器，192结果

使用retarget24；固定输出camera、root/layout、B局部pose和渲染codec，只改变 `beta_B` / `beta_A`，各自重新渲染全部条件。两个生成器为Union基线与选定Pro候选，24×2shape×2模型×2seed=192。

这样几何因素仅是shape。**不可直接拿“原B camera”与“A camera”两版当shape-only对照**。评价目标分成动作保留、A体型代理、源ID和背景。没有真实C*图，不能报对B的PSNR/SSIM为任务质量。

### E07b：布局政策，48结果

固定A-shape与选定生成器，在retarget24的dev12子集比较 `driver_camera` / `source_scene_view_relative` 两种05定义的政策，12×2×2=48。它回答场景/尺度和root位置，不再声称只改变shape。

### E07c：双人接触，32结果

固定8条双人任务、source_scene布局、A-shape和生成器，比较不求解/有界接触求解，8×2×2=32。保存requested/solved；求解失败必须按05规则回退并标记。分别统计几何残差和成图接触，不能将两者互换。

## 11. E08：分辨率和局部修复

基线与选定候选各做512直出、1024直出、512真实stage1＋768局部脸/手修复，val24×2方法×3路径×2seed=288最终结果。粗图已完全同条件存在时可复用；ROI路径额外生成次数、VLM/VAE调用和时间另计。

相同val集合、同身份有效性原则，不拿512 test和1024 val均值直接相减。局部修复保持目标头向/表达，检查外部区域像素和拼接边界；BFS LoRA属于额外开关，初次主实验默认不加，以免把LoRA效应与局部分辨率混在一起。

## 12. E09：扩大验证和冻结测试

最多3个候选在val96×2seed上评价，共576结果。候选数包含系统基线，不能只有不同新模型。冻结输入规则、scope、gate、checkpoint选择、阈值与几何政策后再运行holdout。

若既有holdout确为1024对，可先预算两个最终方法×1024对×1预登记seed=2048结果；是否执行由实际数据审计和前阶段结果决定，不在当前计划中自动排队。完整失败与覆盖必须保留。泛化不足时回到对应假设，不在test上继续调设置。
