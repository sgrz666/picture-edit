# 身份保持与体型解耦研究路线

**目标**：回答“哪条控制路径能在相同姿态精度下保留更多A身份”，并让几何目标真正对应A体型与B动作。范围包括单人与双人，不把体型保持缩减为脸相似度。

**总体结构**：保留Qwen原生source reference，以Union提供原生DiT结构控制先验；以Pro作为可恢复的实验平台，逐步拆出身份路径和可信重定向条件。

**技术范围**：Qwen-Image-2.1、固定VideoX-Fun Union、PyTorch、现有SMPL/SMPL-X和DWPose/ArcFace评测；暂不升级环境、不换基座、不增加大型预训练网络。

## 1. 需要回答的六个问题

| 编号 | 假设 | 证伪方式 | 决策影响 |
|---|---|---|---|
| H1 | ID下降有相当部分来自源身份条件缺失/分辨率不足 | 同checkpoint、同几何下，加入有效源脸裁图仍无稳定收益 | 不继续堆裁图，检查模型是否读取身份、输入是否冲突 |
| H2 | 全joint控制hint扰动参考表征，损伤原生编辑能力 | target-only比joint不能改善姿态–ID取舍，或姿态显著损失 | 保留joint作为候选，不能仅凭“理论更干净”换默认 |
| H3 | 独立ID支路直接写base可能比写control后经过Union输出更有效 | 相同ID模块、等预算、等监督下，base路径不优于control路径 | 不为base注入保留额外工程复杂度；V1共享融合的净效应另做匹配对照 |
| H4 | 有效直接ID监督比新增网络模块更关键 | “只加监督”无收益而“只换结构”稳定有收益 | 调整优先级，以实际2×2实验为准 |
| H5 | 源体型重定向能降低控制目标与身份/外观的冲突 | 在相同相机/落点下，beta_A替换beta_B无收益或生成更差 | 查源shape估计和条件分布；不直接归因于Adapter |
| H6 | 身份损失的一部分受目标脸token分辨率限制 | 同样本同checkpoint提高目标分辨率/ROI仍无改善 | 不把显存投入当成默认解法 |

H1—H6允许同时成立，也允许只在某些子集成立。每份实验结论必须写支持范围，不用一个总体均值覆盖大侧脸、遮挡和双人失败。

## 2. 三条候选技术路线

**推荐主线：现有Pro/Union上做任务解耦。** 优点是官方结构先验、已有数据与恢复工程可用；可以逐一修改reference、hint作用范围、ID输出与loss，诊断成本最低。风险是Union已有控制偏好较强，冻结输出路径可能难以纠正；这需要实验，而不是先全解冻。

**备选：原生Qwen task adapter，不依赖完整Union。** 复用源外观bank、几何前端，直接读取目标hidden并输出独立残差。先在主线稳定评测下实现一个窄对照，再考虑逐层Qwen-native控制核心。没有必要一开始重写完整Full，或以从零训练结果不足证明轻量路线无效。

**保留基线：Full及现有轻量Body/Face。** 它们有历史权重与明确失败案例，用于理解旧能力；优先复用前端、监督和数据经验。暂不把“Full再训练更久”作为主研究投入。

选择由联合效果决定。若独立ID支路在Pro上有效，之后再问它是否需要完整Union；这样能把任务模块价值与骨干规模价值分开。

## 3. 阶段安排

| 阶段 | 要做什么 | 主要产物 | 进入下一阶段的条件 |
|---|---|---|---|
| P0 可信起点 | 对账源码/权重/输入，冻结数据和指标，核查已有Pro验证结果 | baseline_inventory、数据锁、身份覆盖表、可复现运行清单 | 关键来源与输入已知，训练/val/test无已知身份泄漏 |
| P1 几何与输入诊断 | 单独审计重定向、相机、姿态guide；做源脸/控制图实验 | 几何三态面板、E01—E03报告 | 控制条件语义明确，伪骨架/错人/尺度问题已分类 |
| P2 注入机制与监督 | 比较joint/target-only；做结构×loss的2×2训练 | E04—E05、残差/梯度诊断、配对成图 | 工程门禁通过；至少一个候选在验证集上有可信联合收益或明确失败原因 |
| P3 重定向联动 | 固定生成器比几何、固定几何比生成器；解决A场景落点与接触 | E07、source_shape任务包、配对GT策略说明 | 跨体型条件无假GT；几何与生成两层收益可分开解释 |
| P4 分辨率与精修 | 对已选候选做1024和局部ROI，检查头向/表达回退 | E08、质量/耗时/显存表 | 增量价值超过姿态/伪影代价；否则删除该候选配置，保留证据 |
| P5 冻结与泛化 | 固定checkpoint和协议，扩展val，再执行最终holdout | E09、模型卡、失败集与复现说明 | 已满足预登记的联合效果与覆盖要求 |

P0和P1中的几何CPU审计可与阅读历史报告交错开展；本计划执行仍保持单智能体。P3的几何接口设计应在P1开始，不能等训练完才发现条件/GT协议不成立。

## 4. 什么情况下才算“改进”

全部数值是**拟采用的开发门槛**，不是合同验收或已有实验结果。先在P0用检测器重复性、源/目标同人跨视角参考和人工盲评校准一次，签入协议；看到候选结果后不得再调整。

- 优先比较相同姿态水平的ID，或相同ID水平的姿态，报告Pareto曲线，不只报最优单点。
- 开发筛选建议：配对ArcFace平均增量≥0.02、PCK@0.02下降不超过0.02、有效身份覆盖下降不超过5个百分点；并且头向、表达、人数和伪影未明显恶化。
- 反方向也接受：在身份非劣情况下显著改善姿态、接触或大体型差场景。不得要求每个候选只优化一个预选指标。
- “值得扩大验证”不等于“优于基线”。最终结论需要按独立身份/视频聚类的不确定性、第二个训练seed、相同有效集合与失败覆盖；小组数不足时只报告描述性结果。
- 所有候选报告完整失败数。骨架画进图、身份换人或人体数量错误，不得被高PCK抵消。

工程通过、过拟合loss下降、采样成功、图像效果通过分别记四个状态。Pro旧200步global下降20%的门槛继续保留为历史调试记录，不充当最终质量门槛。

## 5. 第一轮不要做的事

- 不同时改参考图、几何渲染、输出画幅、CFG、网络和loss，然后把改善归于“新Adapter”。
- 不直接开放3.775B Union全部参数；先测任务支路和监督，如容量不足再加明确的control LoRA候选。
- 不把重定向后的A体型几何与原B图像配成flow监督；不把伪目标当真实GT。
- 不继续使用2/8身份有效的六例集作为“身份学习能力已经验证”的依据。
- 不将2D bbox/torso缩放称为完整体型解耦；不将beta一致称为完整FaceID一致。
- 不在test上挑scale/层/提示词，不把多个seed当独立身份，不删除失败图。

## 6. 决策树

1. 几何三态检查不通过：回05处理frame、相机、来源或contact，不开网络训练。
2. native/Union对源脸裁图敏感，但Pro不敏感：优先排查bank有效性、mask、loss及源条件被忽略，不急着增大width。
3. source crop和监督能显著改善共享Pro：先保留最小改动；独立ID路径若无额外收益就不合入主线。
4. target-only仅提高ID但明显掉姿态：记录取舍，继续测局部/时间gate，不直接替换joint。
5. 在正确几何下仍普遍丢ID：进入ID路径、分辨率与有限步身份监督；不要用更强几何scale补偿身份问题。
6. source_shape比driver_exact差：先区分shape估计错误、相机错、离开控制分布、无GT评分错四类；只有排除前三类之后才讨论生成器容量。
7. 单人有效但双人失败：先看person mapping、owner/visibility和两人ID覆盖，再看接触与跨人attention。禁止把目标人物之间的所有attention硬切断。
