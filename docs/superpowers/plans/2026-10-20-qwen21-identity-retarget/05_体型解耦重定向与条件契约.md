# 体型解耦重定向如何与Adapter建立联系

**目标**：让控制目标是“A的身体形状，执行B的动作，并符合指定输出场景”，而不是把B的身体投影缩放后要求网络同时保住A。

**设计原则**：几何阶段负责生成自洽的目标约束，Adapter负责把这些约束与A的外观结合。分别检查两阶段，不能让网络替错误相机/错误体型背锅，也不能用正确输入beta证明输出人物体型已经正确。

## 1. 三种不同层次，不要都叫重定向

| 层次 | 做了什么 | 能说明什么 |
|---|---|---|
| 2D framing | 把B关键点按bbox或torso统一缩放、平移到A画布 | 调整屏幕大小和位置；不能改变肢段比例、体宽或遮挡关系 |
| 3D shape retarget | `M(beta_A, theta_B)`重新求mesh/joints | 用A的模型形状承载B局部动作；需要同family/语义兼容的body model |
| Scene/contact retarget | 在明确camera/layout下调整root与少量pose，保持shape、接触/支撑约束 | 解决A场景、双人肢体接触与可达性；约束可能不可同时满足 |

当前workflow的 `align_to_source_bbox` 属于第一层；Pro的 `retarget_request` 属于第二层，`solve_contacts`覆盖第三层的一部分。

## 2. 当前代码已经做到哪一步

已核对现有实现：

- `SourceShape`携带family、稳定person_ids、每人10维betas。
- `BodyParameters`携带body pose、global orient、transl、frame；SMPL-X另有手、jaw与expression，SMPL没有这些字段，不能伪造。
- `retarget_request`只替换betas，保留driver的动作、global orient、translation和camera，输出 `driver/requested/solved` 三态；初始solved=requested。
- `source_rest_heights_m`来自源shape零姿态mesh的Y向高度，不是当前姿态bbox高度。
- 接触求解只调整body pose和root translation，保持shape、手、face、root orientation与camera固定；有5% rest身高和5°限制，失败回退requested。
- 当前 `solve_contacts` 在没有contact edge时直接返回，**不会单独优化传入的anchor/ground**。A场景落点/脚底支撑要有独立布局步骤，或显式扩展该行为并加测试，不能误以为已有ground参数就一定执行。
- `prepare_geometry`每次从选定状态重渲染；typed normal、depth、mask、visibility、part、contact和native control都有来源；source_shape标记unpaired并拒绝旧GT训练。
- 现有 `require_exact_gt_pairing`主要比较参数/mesh/joints；GeometryRequest只有一个共享camera字段。新增布局后必须另核对原GT的camera/layout/画布绑定，不能仅因旧函数返回True就允许源camera重投影继续配原B图。
- 远端 `source_torso`已优先使用实测A躯干，常数0.31只是fallback。本地共享geometry仍旧，实施前对账。无论使用哪种，二维torso匹配都不能当作3D体型解耦。

本次比对：Pro `geometry.py` SHA前缀`bc3cdb46`、`geometry_preparation.py`前缀`27c5a9f6`两侧一致；共享 `src/pose_edit/geometry.py` 本地`86f5b109`、远端`fd274512`不同。

## 3. 明确每个变量来自谁

定义最终目标几何：

```text
V* = BodyModel_A(beta_A, local_pose_B + bounded_pose_correction,
                root_orientation_policy(A,B), root_translation_policy(A,B),
                hand_pose_B_if_available, expression_policy(A,B))
G* = Render(V*, output_camera, output_canvas)
```

| 变量 | 默认来源/政策 | 不允许的替代 |
|---|---|---|
| body shape / limb proportions | A的可靠shape；需要一致的body backend | 为贴近B关键点而优化A的betas |
| 脸身份 | A的source图、FaceID和高分辨率脸特征 | B脸RGB、B身份embedding |
| body局部关节姿态 | B的可靠动作，必要时有界修正 | 复制B的2D长度来替代局部旋转 |
| head orientation | B的目标头向，经指定坐标政策转换 | 把A头向复制回去获得高ID |
| expression / jaw | 默认B有效表达；无效时明确保留A或标为未知 | 把无数据的全零表达叫有效中性真值 |
| hand articulation | B的有效手部参数，同模型语义下迁移 | SMPL假装拥有SMPL-X手指/表情 |
| camera / crop | 根据任务声明输出camera，再做可追溯canvas变换 | 用任意缩放补偿camera错，再称物理尺寸正确 |
| root / layout | A场景编辑时锚定A场景；driver场景复现时保留B | 一个run中混用A/B的坐标和单位 |
| 双人身份映射 | 显式A_i→B_role_j→output_person_id | 按每帧检测框大小重新排序 |

SMPL-X的10维betas不是完整脸身份编码，也不表示衣物厚度/发型。即使mesh shape正确，生成脸和服饰仍需source条件与相应监督。

## 4. 输出相机与布局：第一版定义三种政策

### R1：`driver_camera`，几何诊断基线

保持B camera、global orient和root translation，仅替换为A shape。这与当前 `retarget_request`一致，最适合隔离shape的机械影响；但不保证保留A场景中的位置与透视。

用于 `driver_exact` 时连shape也必须与B原参数相同，否则不再有原B图精确GT。这个政策不自动适用于最终交付编辑任务。

### R2：`source_scene_view_relative`，A场景编辑主候选

1. 使用A的相机估计和已记录画布变换，固定A shape。
2. B的局部关节旋转迁移；目标朝向按“相对于相机的动作”解释，把B camera坐标下的root/head朝向映射到统一CV轴约定，再在A camera轴下执行。这个约定不是声明A/B两个场景有真实共同世界坐标。
3. root位置以A的源pelvis视线/深度估计为初值；在合理范围调整，保持人物在指定画布、地面/接触锚点合理。A的源root depth不可靠时标记估计不确定性，不编造已知厘米尺度。
4. 不强制当前姿态的bbox/torso像素长度等于A源姿态：弯腰、仰头、透视缩短会自然改变它们。应保持canonical shape、相机与明确的场景锚点，而不是每张图都把bbox拉回一样大。

同一轮shape因子实验固定camera与root/layout解，只改变betas；研究布局时才允许root/camera政策变化。把两者混在一起将无法归因。

### R3：`shared_world`，仅限有共同标定坐标的任务

如Hi4D同一采集场景且外参可验证，使用共同world frame，把B的world动作通过输出camera投影。CV定义为+x右、+y下、+z前；`X_cv = R * X_world + t`，row/column实现遵循当前Camera接口。

跨独立拍摄场景没有公共world frame，不能把两套extrinsic数值相乘当作有效对齐。缺失标定时使用R2并声明view-relative，不伪称world精确迁移。

## 5. A的shape怎样取得才可信

优先使用已有多帧/标定拟合中稳定的A shape；只有单帧时记录遮挡、裁切、拟合残差与体型置信度。对于同身份多帧，研究共享betas、每帧独立pose/camera的拟合方案，避免每帧shape漂移被网络当作动作变化。

不能简单平均不同模型、性别模板或单位下的betas；同模型系数可作为初始化聚合，再用重投影/轮廓/可见性验证。不能平均axis-angle向量当作严格旋转平均。

body backend、family、模板/数据gender元信息、模型文件SHA必须绑定到source；按数据元信息选模型，不从照片猜人的性别。第一轮跨shape实验限定同family且模板语义兼容；跨SMPL↔SMPL-X不直接截断/补零pose向量。

当前request使用一个backend重算driver和requested；跨不同gender模板的A/B可能不能忠实表示B原driver。第一轮限制相同backend，后续才设计双backend的显式semantic mapping，并分别保存driver与source模型来源。不能把这个问题隐藏在beta替换里。

## 6. 双人接触：保A形状，但动作不一定完全可达

两个人的身高/肢段不同，固定B的root相对位置和所有关节角可能无法继续握手/拥抱。不能同时承诺任意体型下“所有角度不变、root不变、接触距离为0”。

建议优先级：身份/shape不变 → 合理人物与接触关系 → 小幅root/局部body pose调整 → 尽量保留B动作。允许的变化与失败必须报告。

步骤：

1. 将B接触声明变为稳定的人物/部位端点，例如A0右手接A1左肩；保留置信度和接触类型。
2. 同拓扑时可用已审计vertex端点，跨模型时不能照抄vertex index，需要语义部位/表面对应，否则拒绝该模式。
3. 将两人置于输出布局，重新计算requested mesh中的实际距离、可见性和接触边，而不是沿用旧B raster。
4. 先采用现有5% rest身高、5°body修正的有界求解，记录每条约束误差；第一轮不放开手指、beta或camera来掩盖失败。
5. 求解后重新渲染normal、depth、owner、ROI、contact，更新所有指纹。
6. 若约束不收敛，返回requested并标记 `feasibility="fallback_requested"`；最终效果统计中保留。不得把fallback称为“接触已满足”。

当前约束不包含完整碰撞保证。新增碰撞检查应作为独立验证器，先检测穿透/地面支撑，再决定是否给solver增加项；不同拓扑/尺度误差下不能用统一厘米阈值。脚部ground与anchor-only场景需要独立测试，不能依赖无contact时的早返回。

## 7. 拟新增的几何–Adapter契约

由新文件 `src/pose_control/qwen21_pro/geometry_contracts_v2.py` 定义 `RetargetConditionContractV2`。这是元数据/一致性契约，不自动新增网络输入模态。

```text
schema: retarget_condition_v2
task_kind: paired_reconstruction | same_identity_pose | cross_identity_retarget | dual_retarget
geometry_mode: driver_exact | source_shape
supervision_kind: 02中定义的五种之一
source_person_ids / driver_person_ids / output_person_ids
person_mapping: 每个output slot的source与driver角色
shape_source: actor_id、body_family、backend_sha、betas_sha、confidence
pose_source: driver_id、local_pose_sha、head/hand/expression availability
camera_policy: driver_camera | source_scene_view_relative | shared_world
output_camera_sha / frame / units / layout_signature / canvas_transform
state_sha: driver / requested / solved
feasibility: exact | solved | fallback_requested | unavailable
solver_bounds / constraint_residuals / unavailable_reasons
native_control_signature / typed_geometry_signature / roi_signature
paired_rgb_id: 仅监督索引；不包含目标外观特征
```

`geometry_mode`、`camera_policy`和`supervision_kind`是三个不同维度，不能一个`mode`包办。元数据中监督索引放独立supervision绑定，**不透传到现有TaskCondition.provenance的生成条件命名域**；V2运行时只持有生成所需的只读几何子集，训练器单独取得监督许可。

统一生产链：

```text
A source shape/appearance + B pose/contact
→ explicit person mapping and camera/layout policy
→ requested geometry → bounded contact/layout solve → selected final state
→ native control RGB + typed dense tensors + target ROI + valid/visibility/owner
→ encode_condition + TaskConditionV2
→ Union geometry / Pro body appearance / independent ID branch
```

所有支路都消费同一个最终状态签名。不能Union读B原骨架，typed分支读A-shape normals，而脸mask仍来自未求解B位置。

typed depth保持当前共享场景min/max编码，双人使用同一深度范围，原始metric depth和range另存。不得每人单独归一后仍认为近远关系保留。part使用离散编码，normal采用统一camera-CV坐标；无效值由valid mask表达，不用“填0”代替有效中性状态。

当前TaskCondition.spatial严格只有六种模态；新shape统计先进入审计和签名，不随意往129通道或spatial字典插入betas。若以后研究explicit shape token，新增明确的独立字段/encoder和消融，保持兼容性。

## 8. 训练与GT：最容易把项目带偏的一环

**阶段一**：用当前 `paired_driver_exact` 训练可比较的网络机制，先证明ID输入和监督能起作用。它不证明跨体型泛化。

V2配对许可还须核对body backend、物理camera、root/layout和Y到训练画布的明确变换。纯resize/letterbox在Y与条件使用同一变换时可保持配对；换物理视角/人物落点则不能沿用原Y。旧参数相等测试不足以覆盖新增camera政策。

**阶段二**：对same_identity数据研究共享shape重新拟合。只有Y确为A本人、几何与Y对齐经离线审查，才可进入 `paired_identity_refit`；记录拟合容差和权重，仍不是exact。保持旧guard不变，另开审核后的数据分派。

**阶段三**：跨身份A-shape任务先做推理/评测。若需要训练，可选真实多视角/同身份动作数据、独立合成配对、带教师筛选的伪配对，或有限步生成后的ID/几何/背景自监督；每条都要另立研究，不在本轮默认混成监督训练。

无GT生成自监督中的pose估计器可被骨架线等伪影欺骗；必须配合原始图像/伪影审查，不能只优化可微pose score。仅用ID loss也可能收敛到不动人物，必须同时检查目标动作执行。

## 10. 怎样证明这块与ID保持有联系

采用03的E07，而不是展示两张“看起来更像”的图：

- 固定A外观、B动作、camera/root与模型，只换beta，检查输出是否少借用B体型，同时保持动作。
- 固定最终几何，只换Union/Pro，检查网络是否真正把A外观正确绑定到这份几何。
- 检查source→body shape与source→FaceID是两条关系：shape更准确不必然提高ArcFace；ArcFace提高也不等于体型保持。
- 对接触失败记录不可达原因和容差，不迫使网络生成物理上互相矛盾的条件。
- 输出真实条件面板与最终图，人工确认PCK目标确实是C*，没有仍按B原比例惩罚正确A体型结果。

第一版做到“几何目标可解释、GT不矛盾、Adapter读到同一目标”就已经解决关键研究前提；后续效果提升由实验决定。
