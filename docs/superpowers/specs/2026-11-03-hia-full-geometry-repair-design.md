# HIA 全量几何修复方案

日期：2026-11-03。本文是待执行的设计方案，未启动全量 GPU 作业。沿用现有 Sapiens2、DWPose 和 SMPLest-X，第一轮不训练新模型、不升级环境、不修改旧图像、视频或结果。按用户要求，全程由当前智能体执行，不使用 subagent。

## 目标与选择

推荐：全量逐帧评估与候选修复，再按证据选择可采用的结果；疑难侧单独复核和补修。全量覆盖不等于每帧修改，也不等于每帧修复成功。交付应同时包含几何资产与使用质量信息。

不推荐把当前 v3 原样跑完后整体替换，因为 unknown 会保留原始假手。也不推荐第一轮直接放开相机、体型、躯干和手指共同优化，已有 v2 失败证明隐藏手损失可以通过改变整个身体满足目标。

当前 v3 适合作为保守候选生成器。拟规划的全量版本先补未知/裁切处理、选择机制和批处理工程；全身初值明显错误的样本转入单独疑难修复通道，不混入手部局部优化。

## 实施阶段与产物

### 1. 冻结输入与批处理基础

构建发布帧清单，保留原 train/val/test、clip、时间戳或帧号。合并原始几何与 12 帧修复根；同一帧多来源时记录优先级、签名和冲突，不按目录顺序随意选择。排除项保留理由与来源。识别可用 Sapiens 缓存时必须核对输入、bbox、精度、权重和代码身份，缺少身份信息就不能直接复用。

先对 32 帧测完整观测、拟合、渲染、落盘吞吐与峰值显存。模型常驻单 GPU，按帧或小批次处理；不并发加载多个 5B 模型。记录检测框、308 点与分数、DWPose、初始参数及所有来源哈希。每帧临时写入后原子提交完成记录，异常单独记账；断点续跑只复用输入与配置指纹一致且资产校验通过的帧。

产物：`manifest.jsonl`、输入审计、观测缓存、`run.json`、`progress.json`、`failures.jsonl`。发生路径不存在、哈希不符、非有限参数时明确失败，不能静默换输入。

### 2. 补齐质量状态与未知侧处理

分别记录每侧的观测状态、候选动作与质量判断。不能用一个“运行成功”布尔值表示几何可信。

| 证据 | 第一轮处理 | 可采用条件 |
|---|---|---|
| 双手清晰且观测一致 | 局部优化肩、肘、腕、手指；接近不删侧 | 身体保护、可见腕位置与手部形状检查通过 |
| 腕可靠、指节不可靠 | 优化手臂/腕；强前伸证据允许受约束手指候选 | Sapiens-only 手指保留不确定标记，不能冒充独立确认 |
| 隐藏候选 | 固定身体与相机，仅调整对应手臂 | 后表面约束、可见肘保护与可见性检查通过；仍非完整碰撞证明 |
| 可靠出画/裁切证据 | 按图像边界和真实几何裁剪，限制不可见区域参与优化 | 不强制恢复为统一下垂姿态，不向画内拉假手 |
| unknown / 袖口 / 严重模糊 | 保留初值作为候选并标记 review；优先补证据 | 原始假手存在时不能被记为 accepted |
| 人体初值错误/主体混淆/近景严重错位 | 转入疑难通道，保存可视化与原因 | 不由手部损失驱动全身弯曲 |

拟采用质量字段：`decision`（accepted、retained、review、failed、excluded），每侧 `body_valid`、`arm_valid`、`finger_valid` 与 `reason`。`retained` 表示未采用修复，不代表原始几何正确；下游按区域质量使用，不把未知手指当作可靠监督。

000121、000123 必须作为此阶段回归样本。对近景需识别裁切边界、可见前臂与未知腕的区别；对袖口和模糊样本需要额外证据，不能仅调低置信度门槛。禁止直接擦除 normal/depth 的手部像素来伪装几何修复；若 mesh 不可信，应标记和限制使用，并保持各模态语义一致。

### 3. 分层试运行与冻结验收

保留既有 14 个难例作为回归集，新增目标 200 帧用于覆盖清晰可见、接触交叠、前伸、背手、袖口/物体遮挡、运动模糊、近景裁切、镜面/多人等情况。新样本按 clip 隔离分为 100 校准、100 冻结验收；稀缺类别不足时记录实际数量，不复制样本凑数。调参只使用校准与回归集，冻结验收失败后修改配置须留下新版本，不能继续把已看过的验收集称为未见数据。

验收前定义主观条目：新增假手、误藏可见手、身体严重扭曲、明显手臂断裂，以及保留问题是否被如实标为 review。每个抽样帧检查 RGB、原始、v2、候选的骨架/normal/depth；14 个失败样本全查，其余按固定清单查。不能让单一 Sapiens 拟合分数决定采用。

首轮准入目标（目标，不是现有结果）：冻结验收集中，自动接受的候选没有新增严重身体扭曲；可见手误藏不能增加；已知未解决帧不能被误标为修复通过。身体、腕、指分别报告，误差以可靠 torso/bbox 尺度归一化并保留像素值。现有 +2 px 规则需在校准集检查尺度效应，不能不加评估地跨分辨率使用。

在这里固定参数、质量阈值、模型精度和代码指纹后，再启动全量主作业。工程产物全通过不等于上述语义验收通过。

### 4. 全量主修复

处理正式 manifest 中全部可拟合帧，沿用同一冻结配置。以 clip 或固定分片组织任务，单帧失败不终止整批；重试使用受控次数并保留原错误。报告已处理、accepted、retained、review、failed、excluded 的数量，记录速度、显存、最近错误和预计剩余时间。

每帧从原始一致的 SMPLest-X 参数启动；v2 只作对照，不能接力累积它的变形。保存原始与候选参数、选择结果、区域质量、normal、可视/数值 depth、骨架、相机、输入哈希和代码身份。检查保存参数可以重建对应 mesh，禁止参数、mesh 和图板来源不一致。

全量遍历完成后，对 accepted、retained、review 分别按场景抽查；尤其检查“保留初值”是否被下游当作可靠修复资产。第一轮发现问题时只重跑受影响分片，不覆盖旧轮次。

### 5. 疑难帧二次修复

优先处理 review 中数量最多、下游影响最大的类别，并复用观测缓存：

- 同 clip 前后参考：先核对时间戳、帧间距、人物和镜头。当前平均每 clip 只有少量发布帧，不能假定它们连续，也不能跨大动作强行平滑。必要时只对疑难 clip 从源视频补短窗口邻帧，保持 split，不修改原视频。
- 近景与裁切：单独约束可见前臂和画面边界，处理边缘假手；缺少证据时保留 review。
- 袖口/物体遮挡：审计是否已有可复用的分割或可见性资产；没有可靠资产时不宣称靠 score 恢复了隐藏手形。
- 身体本身错误：单独生成身体候选，只在可靠躯干观测支持下进行强先验、限幅优化；固定体型/焦距，身体候选验收后再冻结并处理手。此通道不继承手部“躯干漂移为零”的评价方式，需独立校准；首轮先保留 review，不把未实现的身体优化描述为已有功能。

二次修复产生独立候选与新版本记录；无法确认的帧继续留在 review，不通过降低门槛追求表面 100% 成功。

### 6. 最终交付与下游接入

数量闭合：发布 manifest 的每个 frame_id 恰好对应一个最终决定，去重后满足 accepted + retained + review + failed + excluded = 总量。22,275 为历史上预计有几何的规模，须以本轮集合审计为准。

为每帧选择整套几何资产，参数、骨架、normal、depth 保持来自同一候选；不拼接不同轮次的单张图。提供 `selected_manifest.jsonl`、区域质量字段、排除/复核清单、分类统计与抽查图板。旧 split、原始图像和旧结果不变。下游训练先使用明确可信的区域；unknown/不可靠指节不作为可靠手部监督。具体训练缓存改动需单独核对已有消费者契约，不能只替换路径。
